# 对接文档：战斗模块 ↔ 外部数据模块

> 版本：**v1.0**（依据《接口文档_战斗服务.md》**v1.9**，2026-09-10）
> 读者：**外部数据模块**（宝可梦数据 / 成长规则的提供方）开发者，以及**战斗模块侧**的组装层开发者
> 目的：明确两侧边界、接口用途、已有能力、所需数据与各自待办，使外部数据模块能以最小改动接上战斗模块

---

## 一、角色与边界

| 模块 | 角色 | 负责 | **不负责** |
|------|------|------|-----------|
| **战斗模块**<br>`org.example.battle` | 引擎（消费方） | 回合演算、伤害与状态结算、道具消费、胜负判定、把结算结果**申报**出去 | 不内建数据、不查数据库、不生成遭遇、不判定成长（经验 / 升级 / 学招 / 进化） |
| **外部数据模块**<br>`org.example.data` / `org.example.pokemon` / `org.example.growth` | 数据与规则提供方 | 技能、种族、野生池、个体生成；经验 / 升级 / 学招 / 进化规则 | 不参与回合演算，不修改战斗流程 |
| **组装层**<br>`org.example.integration`、控制器 | 唯一注入点 | 创建端口实现、注入工厂 | 不实现战斗规则、不实现数据规则 |

```
        ┌──────────────────────────────┐
        │  外部数据模块                  │
        │  · 技能 / 种族 / 野生池 / 个体   │  实现 BattleDataPort
        │  · 经验 / 升级 / 学招 / 进化     │  实现 BattleGrowthPort
        └───────────┬──────────────────┘
                    │ 由组装层 new 出来
        ┌───────────▼──────────────────┐
        │  组装层（PokemonBattleAdapter）│
        │  MainController / BattleConsole│
        └───────────┬──────────────────┘
                    │ BattleServices.newBattle(..., dataPort, growthPort)
        ┌───────────▼──────────────────┐
        │  战斗模块（BattleService 引擎）│  只演算 + 只结算
        │  运行期不反向依赖任何数据模块    │
        └──────────────────────────────┘
```

**核心约定**：战斗模块**不会**主动去「拉」数据源，也不会问成长模块「你想查什么」；
它只在**需要时**经端口查询（学招 / 进化），并在**胜利结算时**把事实申报出去。

## 二、对外接口清单（外部数据模块需要实现）

### 2.1 `BattleDataPort`（**必做**）

全限定名：`org.example.battle.BattleDataPort`（接口，只读）
默认空实现：`org.example.battle.BattleDataPorts#none()`

| 方法 | 用途 | 谁在调用 | 何时调用 | 返回约定 |
|------|------|---------|---------|---------|
| `Move findMove(String moveId)` | 按 id 取技能对象 | 成长模块（`GrowthService#learnAt`） | 精灵升级、到达习得表等级、需要学会新招时 | 查不到返回 `null` → **静默跳过学招**，不抛异常 |
| `Species findSpecies(String speciesId)` | 按 id 取种族对象 | 成长模块（`GrowthService#evolve`） | 精灵满足进化等级、需要换形态时 | 查不到返回 `null` → **静默跳过进化** |
| `List<String> wildSpeciesPool()` | 可随机遭遇的种族 id 池 | 组装层（`WildEncounter.randomWild`） | 流程系统要生成一场野生遭遇时 | 无可用野生种族时返回**空列表** → 无法遭遇 |
| `Optional<Pokemon> createPokemon(String speciesId, int level)` | 按种族 + 等级生成个体 | 组装层（`WildEncounter.randomWild`） | 生成野生精灵时 | 失败返回 `Optional.empty()`；**接口自带默认实现**（见下） |

**`createPokemon` 的默认实现**（方法上已给默认体）：按 `Species#getMoveIds()` 顺序取技能，
最多 `Pokemon.MAX_MOVES`（4）个，跳过查不到的技能，然后 `Pokemon.create(species, level, moves)`。

> 建议数据模块**覆盖**此方法：按等级筛选可学技能（用习得表），而不要直接用「出生技能」，
> 否则 20 级遭遇的野生精灵只会有 1 级技能。

**返回对象的所有权**：引擎会**就地修改**返回的 `Pokemon`（HP、PP、异常状态、等级、技能栏）。
每次调用必须返回**全新实例**，不可缓存复用同一个对象。

### 2.2 `BattleGrowthPort`（**建议做**）

全限定名：`org.example.battle.BattleGrowthPort`（接口，声明在引擎侧供跨模块共享）
默认空实现：`BattleGrowthPort.none()`
仓库内参考实现：`org.example.growth.GrowthService`（可直接复用或替换）

| 成员 | 形态 | 用途 |
|------|------|------|
| `Settlement settle(List<Pokemon> survivors, List<Pokemon> defeated)` | 方法 | **胜利结算申报**：引擎把「参战且未倒下的己方精灵」与「被击败的对手」交给外部模块，由外部判定经验、升级、学招、进化 |
| `List<String> resolveLearn(LearnChoice choice, int forgetSlotIndex)` | 方法 | **执行一项学招抉择**：替换槽位，或传 `-1` 放弃学习 |
| `Settlement(List<String> log, List<LearnChoice> pendingLearns)` | `record` | 结算结果：`log` 是要追加到战斗日志的文本行，`pendingLearns` 是技能栏已满、需玩家抉择的挂起项 |
| `static BattleGrowthPort none()` | 静态方法 | 空端口：不判定任何成长 |

`LearnChoice` 是 `BattleService.LearnChoice`：`record LearnChoice(Pokemon pokemon, Move move)`。

**入参含义**（引擎侧已做好的预处理，外部模块不必重复判断）：

- `survivors`：玩家队伍中**未倒下**的精灵（引擎已过滤；可能为空列表）；
- `defeated`：野生遭遇为**单只野生精灵**；训练师轮战为**整队被击败的对手**（求和在外部做）；
- 仅在 `Status.PLAYER_WIN` 时调用；其它状态（逃跑 / 捕捉 / 战败）**不会**触发成长申报。

### 2.3 需要外部数据模块「提供」但不属于端口的对象

这些对象由组装层构造后**直接传给引擎**，端口不参与：

| 对象 | 谁提供 | 说明 |
|------|--------|------|
| `Player` | 组装层 / 宝可梦系统 | 含队伍 `List<Pokemon>` 与背包 `Bag` |
| `Trainer` | 流程系统 | 含名字与整支队伍（训练师轮战用） |
| `Item` 实例 | 道具数据模块 | 引擎只按 `ItemCategory`（`HEAL` / `CURE` / `POKE_BALL`）分流，**不按 id 认识道具** |
| `Weather` / `Terrain` | 引擎内部按技能效果推导 | 数据侧只需保证 `Move.effect` 正确 |

## 三、战斗模块已有功能（外部模块可直接消费，无需自己实现）

### 3.1 接口：`BattleService`

| 能力 | 方法 | 说明 |
|------|------|------|
| 出招 | `List<String> useMove(MoveSlot slot)` | 按速度决定先后手；`null` 或 PP 耗尽时自动退回第一个可用技能 |
| 用道具 | `List<String> useItem(Item item, int partyIndex)` | 可指定队伍任意精灵（含替补）；原单参重载为 `default` 委托 |
| 逃跑 | `List<String> tryRun()` | 仅野生遭遇；成功率随速度提高（`0.35 + 0.6 × 速度占比`） |
| 换精灵 | `List<String> switchActive(int partyIndex)` | 消耗本回合行动 |
| 查状态 | `getStatus()` / `isOngoing()` / `getLog()` | `Status`：`ONGOING` / `PLAYER_WIN` / `PLAYER_LOSE` / `FLED` / `CAUGHT` |
| 查对象 | `getPlayer()` / `getWild()` / `getTrainer()` / `foeActive()` / `playerActive()` | 野生战 `getTrainer()==null`；训练师战 `getWild()==null` |
| 查环境 | `getWeather()` / `getTerrain()` / `getBag()` | 天气与场地由变化类技能开启 |
| 学招抉择 | `pendingLearnChoices()` / `decideLearn(int)` | 队列由引擎管理，**判定文本由成长模块产生** |

### 3.2 已实现的演算规则

- **伤害**：`(2×等级/5 + 2) × 威力 × 攻击/防御 ÷ 50 + 2`，再乘 STAB(1.5) × 属性相性 × 天气/场地倍率 × 随机浮动 `0.85~1.00`，最低 1 点；
- **先手**：由 `Pokemon#effectiveSpeed()`（含麻痹减半等）决定；
- **异常状态**：中毒 / 剧毒 / 麻痹 / 灼伤 / 睡眠 / 冰冻 / 混乱，含回合末持续伤害、麻痹不行动、灼伤降攻击、混乱自伤等；
- **天气与场地**：`SUNNY_DAY` / `RAIN_DANCE` / `SANDSTORM` / `SNOW`、`ELECTRIC` / `GRASSY` / `PSYCHIC` / `MISTY` 等，含招式威力与回合末效果；
- **道具**：回复（`HEAL`）、解除异常（`CURE`，支持多项与 `ALL`）、捕捉（`POKE_BALL`，含必定捕获）；
- **捕捉**：`(3×最大HP − 2×当前HP) ÷ (3×最大HP) × 种族捕获率 × 球倍率 ÷ 255`，上限 98%；成功后加入玩家队伍；
- **训练师轮战**：不可逃跑、不可捕捉，**任一方整队全部倒下才结束**，敌方倒下自动换下一只；
- **日志**：所有行动方法返回「本回合**新增**」的日志行，`getLog()` 返回完整只读日志。

### 3.3 工厂：`BattleServices`（共 12 个重载）

| 类型 | 签名族 |
|------|--------|
| 野生战 | `newBattle(player, wild[, random][, dataPort][, growthPort])` |
| 训练师战 | `newTrainerBattle(player, trainer[, random][, dataPort][, growthPort])` |

**不传端口的重载内部等价于注入 `BattleDataPorts.none()` + `BattleGrowthPort.none()`**，因此既有代码零改动。

### 3.4 战斗模块**不会**做的事（请外部模块认领）

- ❌ 经验数值计算、升级、学招、进化（→ `BattleGrowthPort`）
- ❌ 野生遭遇的「遇到谁、几级」（→ 组装层 `WildEncounter`）
- ❌ 道具的获取途径与数值（→ 道具数据模块）
- ❌ 敌方 AI 的「聪明程度」（当前为随机可用技能；若要增强策略需新增端口）
- ❌ 训练师队伍的生成与强度（→ 流程系统 / 肉鸽系统）

## 四、使用方法

### 4.1 三步接入

1. **实现 `BattleDataPort`**（4 个方法）→ 得到数据端口实例；
2. **实现 `BattleGrowthPort`**（可复用 `org.example.growth.GrowthService`）→ 得到成长端口实例；
3. **在组装层注入**：把两个端口传给 `BattleServices` 或 `BattleEngine`。

### 4.2 最小可用示例（野生战 + 完整数据 + 成长）

```java
// 1) 数据端口：数据模块的适配器
BattleDataPort dataPort = new MyDataModulePort();          // 或 new GameDataBattleDataPort()

// 2) 成长端口：复用现成实现（与战斗模块共用同一份数据）
BattleGrowthPort growthPort = new GrowthService(dataPort);

// 3) 注入
BattleService battle = BattleServices.newBattle(player, wildPokemon, dataPort, growthPort);

// 4) 驱动回合
battle.useMove(battle.playerActive().getMoveSlots().get(0));
while (battle.isOngoing()) { /* 按 UI 事件推进 */ }
```

### 4.3 处理「技能栏已满」的学招抉择

```java
// 战斗结束（PLAYER_WIN）后，成长模块可能挂起若干抉择
for (BattleService.LearnChoice choice : battle.pendingLearnChoices()) {
    // 让玩家决定：遗忘哪一格（0~3），或 -1 放弃
    int forgetSlot = ui.askForgetSlot(choice.pokemon().getMoveSlots(), choice.move());
    List<String> lines = battle.decideLearn(forgetSlot);   // 引擎转发给成长模块并出队
    render(lines);
}
```

> 队列由引擎管理，**必须先 `pendingLearnChoices()` 判断非空**，否则 `decideLearn` 会抛 `IllegalStateException`。
> 精灵有空格时新技能已自动学会，不会进入该队列。

### 4.4 训练师战

```java
Trainer rival = new Trainer("劲敌");
rival.addToParty(monA);   // 整队
rival.addToParty(monB);
BattleService battle = BattleServices.newTrainerBattle(player, rival, dataPort, growthPort);
// 任一方整队全部倒下才结束；不可逃跑、不可捕捉
```

### 4.5 自定义数据端口实现（从 Map / 配置载入）

```java
public final class MyDataModulePort implements BattleDataPort {

    private final Map<String, Move> moves;
    private final Map<String, Species> species;
    private final List<String> wildPool;

    @Override public Move findMove(String moveId)        { return moves.get(moveId); }
    @Override public Species findSpecies(String speciesId){ return species.get(speciesId); }
    @Override public List<String> wildSpeciesPool()       { return List.copyOf(wildPool); }

    @Override
    public Optional<Pokemon> createPokemon(String speciesId, int level) {
        Species sp = findSpecies(speciesId);
        if (sp == null) {
            return Optional.empty();
        }
        // 覆盖默认实现：按等级从习得表里挑技能，而不是直接用「出生技能」
        List<Move> learned = new ArrayList<>();
        for (int lv = 1; lv <= level && learned.size() < Pokemon.MAX_MOVES; lv++) {
            String moveId = sp.moveLearnedAt(lv);
            Move m = findMove(moveId);
            if (m != null && learned.stream().noneMatch(x -> x.getId().equals(m.getId()))) {
                learned.add(m);
            }
        }
        return Optional.of(Pokemon.create(sp, level, learned));
    }
}
```

### 4.6 自定义成长规则实现（替换默认经验公式）

```java
public final class MyGrowthService implements BattleGrowthPort {

    private final BattleDataPort dataPort;

    public MyGrowthService(BattleDataPort dataPort) { this.dataPort = dataPort; }

    @Override
    public Settlement settle(List<Pokemon> survivors, List<Pokemon> defeated) {
        List<String> log = new ArrayList<>();
        List<BattleService.LearnChoice> pending = new ArrayList<>();
        int exp = /* 自定义公式：例如只看等级差、加道具加成 */ 0;
        for (Pokemon p : survivors) {
            if (p.addExp(exp) > 0) { log.add(p.getName() + " 升到 Lv." + p.getLevel() + "！"); }
            // 学招 / 进化的判定完全由本模块决定
        }
        return new Settlement(log, pending);
    }

    @Override
    public List<String> resolveLearn(BattleService.LearnChoice choice, int forgetSlotIndex) {
        return List.of();   // 自行实现遗忘 / 放弃逻辑
    }
}
```

## 五、需要的数据

### 5.1 数据对象契约

**`Move`（技能）** — 构造：`new Move(id, name, ElementType, MoveCategory, power, accuracy, maxPp, priority, MoveEffect, StatusCondition inflicts, int inflictionChance)`

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` / `name` | ✅ | 唯一 id、显示名 |
| `type` | ✅ | `ElementType` 枚举名（如 `GRASS`） |
| `category` | ✅ | `PHYSICAL` / `SPECIAL` / `STATUS`（变化类 `power = 0`） |
| `power` | ✅ | 招式威力；变化类为 0 |
| `accuracy` | ✅ | 命中率（`-1` 表示必中）；**当前引擎未做命中判定**，仅存档 |
| `maxPp` | ✅ | 最大 PP，必须 ≥ 1 |
| `priority` | ✅ | 先制度（当前引擎未消费，按速度决先手） |
| `effect` | ✅ | 天气 / 场地等变化效果（`MoveEffect`），无则 `NONE` |
| `inflicts` / `inflictionChance` | ⬜ | 命中后可能施加的异常状态与概率（%） |

**`Species`（种族）** — 构造：`new Species(id, name, type1, type2, Stats baseStats, catchRate, List<String> moveIds, evolvesToId, evolveLevel, Map<Integer,String> learnAt)`

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` / `name` | ✅ | 唯一 id（**必须与 `findSpecies` 的 key 一致**）、显示名 |
| `type1` | ✅ | 主属性；`type2` 可 `null` |
| `baseStats` | ✅ | `new Stats(hp, attack, defense, spAttack, spDefense, speed)`，用于属性演算与经验折算 |
| `catchRate` | ✅ | 1~255（越高越好抓），野生捕捉直接用它 |
| `moveIds` | ✅ | **出生即会**的技能 id（默认实现取前 4 个） |
| `evolvesToId` / `evolveLevel` | ⬜ | 进化目标 id 与等级（`evolveLevel = 0` 表示不进化） |
| `learnAt` | ⬜ | 习得表 `等级 → 技能 id`，`moveLearnedAt(level)` 取用 |

**个体**：`Pokemon.create(Species species, int level, List<Move> movePool)`；引擎与成长模块只通过
`Pokemon` 的公开方法（`addExp` / `evolveTo` / `learnMove` / `replaceMove` / `getMoveSlots` 等）操作它。

### 5.2 数据一致性硬约束（违反会**静默失效**，不报错）

| # | 约束 | 违反后果 |
|---|------|---------|
| C1 | `Species.moveIds` 中每个 id 都能被 `findMove` 查到 | `createPokemon` 默认实现会跳过查不到的技能 → 个体可能 **0 个技能**，战斗无法行动 |
| C2 | `Species.learnAt` 中每个 moveId 都能被 `findMove` 查到 | 到级学招静默跳过 |
| C3 | `Species.evolvesToId` 能被 `findSpecies` 查到 | 到级不进化（静默） |
| C4 | `0 ≤ evolveLevel ≤ 100` | 超出 `MAX_LEVEL` 则永不触发 |
| C5 | `wildSpeciesPool()` 非空，且每个 id 都能被 `findSpecies` 查到 | 无法生成野生遭遇（`WildEncounter.randomWild` 返回空） |
| C6 | 1 级个体至少有 1 个可用技能（PP > 0） | 玩家出招时「无可用技能」，本回合不行动 |
| C7 | `type1`/`type2` 必须是合法 `ElementType` 名 | 属性相性计算异常 |
| C8 | 每次 `createPokemon` 返回**新实例** | 复用同一实例会导致 HP / 等级 / 状态互相污染 |
| C9 | `Move.maxPp ≥ 1`、`Species.catchRate ≥ 1` | PP 为 0 即不可用；捕获率会被除数放大/缩小 |

## 六、需要外部数据模块完成的功能（交接清单）

| 编号 | 事项 | 优先级 | 验收方式 |
|------|------|--------|---------|
| **D-01** | 实现 `BattleDataPort` 四个方法（`findMove` / `findSpecies` / `wildSpeciesPool` / `createPokemon`） | **P0** | 端口注入后野生遭遇能生成、战斗可正常出招 |
| **D-02** | 保证 `wildSpeciesPool()` 非空且 id 可解析 | **P0** | `WildEncounter.randomWild(...)` 返回非空 |
| **D-03** | 保证 `moveIds` / `learnAt` / `evolvesToId` 全部可解析（C1~C4） | **P0** | 一场胜利后能观察到升级、学招、进化日志 |
| **D-04** | 覆盖 `createPokemon`，按等级筛选技能（不要只给出生技能） | P1 | 20 级遭遇的个体拥有 ≥ 2 个与其等级相称的技能 |
| **D-05** | 提供 `BattleGrowthPort` 实现（或显式复用 `GrowthService`） | P1 | `PLAYER_WIN` 后既有日志行也有实际数值变化 |
| **D-06** | 训练师队伍生成（等级 / 数量 / 技能组合） | P1 | 训练师战可正常轮战至一方全灭 |
| **D-07** | 道具获取途径（当前仅初始发放 8 种，另有 4 种无来源） | P1 | 背包可经流程获得恢复 / 解除 / 球类 |
| **D-08** | 数据自检（启动时校验 C1~C9，给出明确日志） | P2 | 缺数据时启动日志给出可定位的警告 |
| **D-09** | 成长规则收敛为一处（`GrowthService` 与宝可梦系统 `gainExp` 目前各一份） | P1 | 两处口径一致，或只保留一处 |

### 数据模块自检代码骨架（建议）

```java
// 启动时一次性校验，避免战斗中出现「静默无效果」
for (String id : port.wildSpeciesPool()) {
    Species sp = port.findSpecies(id);
    if (sp == null) { log("野生池 id 无种族定义: " + id); continue; }
    for (String mid : sp.getMoveIds()) {
        if (port.findMove(mid) == null) { log("种族 " + id + " 的出生技能缺失: " + mid); }
    }
    if (sp.getEvolvesToId() != null && port.findSpecies(sp.getEvolvesToId()) == null) {
        log("种族 " + id + " 的进化目标缺失: " + sp.getEvolvesToId());
    }
    Optional<Pokemon> p = port.createPokemon(id, 1);
    if (p.isEmpty() || p.get().getMoveSlots().isEmpty()) {
        log("种族 " + id + " 在 1 级时没有任何技能（战斗无法行动）");
    }
}
```

## 八、缺数据时的降级行为矩阵

| 缺失项 | 战斗能否运行 | 影响 |
|--------|-------------|------|
| 完全未注入数据端口（`BattleDataPorts.none()`） | ✅ 能 | 战斗规则照常；学招与进化静默跳过；无法随机遭遇（野生池为空）；**经验与升级仍照常** |
| 未注入成长端口（`BattleGrowthPort.none()`） | ✅ 能 | 胜利后**不做任何成长**，日志无成长相关文本 |
| 野生池为空 | ✅ 能 | 无法生成野生遭遇（`WildEncounter.randomWild` 返回空），需流程侧给提示 |
| 技能查不到（C1/C2） | ✅ 能 | 对应个体可能无技能；学招静默跳过 |
| 进化目标查不到（C3） | ✅ 能 | 不进化（静默） |
| `Move` 全部 PP 为 0 | ⚠️ 可进入战斗 | 出招方法会「不行动」，等于空回合 |

**设计原则**：数据缺失一律**降级而非抛异常**，因此「没反应」通常意味着数据没接上；
请优先按 §5.2 与 §6 D-08 做自检，而不是怀疑战斗逻辑。
