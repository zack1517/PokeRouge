### 二、今日遇到的问题与处置

| 问题 | 处置方式 | 状态 |
| --- | --- | --- |
| 训练师战中敌方面板空白 | `BattleController` 原用 `engine.getWild()` 渲染，改为统一 `foeActive()`；`getWild()` 仅野生遭遇非空 | ✅ 已解决 |
| 换宠当回合新精灵是否会立刻出手 | `useMove` 在 `resolveRoundEnd()` 之前判断出战精灵是否倒下，换上的精灵当回合不行动，已加断言固化 | ✅ 已解决 |
| 本机 git 启用了提交签名但无私钥，commit 失败 | 提交统一加 `--no-gpg-sign`（不改动全局 git 配置） | ✅ 已解决 |
| 训练师战暂无游戏内入口 | `newTrainerBattle` 尚无调用方（主流程仅创建野生遭遇）；按当前范围只交付战斗系统内部能力，入口待流程系统接入 | ⏳ 待接入 |
| 麻痹精灵「无法行动」时仍被扣了 PP | 原实现先 `MoveSlot.use()` 再判定行动；改为 `playerAct` 中**先 `canAct` 再消耗 PP**（`use()` 在 PP 耗尽时返回 false 且不消耗，判定必须前置），并加断言固化 | ✅ 已解决 |
| 解毒药无法解除剧毒（原版应同时解除中毒与剧毒） | 原 `Item.curesSpec` 只支持单个状态；改为按 `[&#124;,\s]+` 分词的多项范围，并把 `i_antidote` 调整为 `POISON&#124;BADLY_POISON`（内建注册与 CSV 同步） | ✅ 已解决 |
| 「只带变化类效果」的招式无法施加异常 | `executeMove` 原在 `MoveEffect.NONE` 时提前跳过；改为「有效果 **或** 带 `inflicts`」都进入结算 | ✅ 已解决 |
| 战斗结束后仍继续推进回合末结算 | `finishRound` 开头增加 `Status.ONGOING` 判定，非进行中直接返回 | ✅ 已解决 |
| 战斗模块直接依赖数据注册表 `GameData`（内建数据 + 直连数据源） | 抽出只读端口 `BattleDataPort`，引擎/工厂改为经端口查询，数据侧提供 `GameDataBattleDataPort` 适配器并在组装层注入；旧签名保留（缺省走空端口 `BattleDataPorts.none()`），`mvn -o test` 76/76 无回归 | ✅ 已解决 |
