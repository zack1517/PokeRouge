### 一、今日完成

- [x] **修复「打赢道馆后不进入下一段」**（试玩反馈）
  - 根因：`GameSession#resolveRogueMandatoryVictory()` / `RogueTurnManager#resolveMandatoryVictory()`
    早已实现并在 javadoc 里写明「由控制器调用」，但**全仓没有任何调用点**——控制器漏接线。
    `MainController#rogueBattleFinished` 的胜利分支只发了金币就调 `finishNodeStep()`，
    而 `RogueTurnManager#advanceAfterNode()` 在必然阶段会直接 `return false`（`phase != EXPLORING`），
    于是阶段永远停在 `GYM`，`afterRogueStep()` 下一拍又开一次道馆战（对手每次重新随机，
    表现为「同段道馆反复打、段落数不涨」）
  - 修复：必然节点（道馆 / 四天王 / 冠军 / 首领侵略战）胜利改走
    `GameSession#resolveRogueMandatoryVictory()`，**金币与阶段流转（下一段 / 四天王 / 冠军 / 通关）
    一次结算**；控制器不再单独调 `awardRogueWinGold`，避免重复发钱
  - 顺带修正 `GameSession#enterRogueSegment(int)` 的地图背景重抽判定：原实现把 `getSegment() != segment`
    写在 `enterSegment(segment)` **之后**，比较永远相等、背景从不重抽；改为先取 `previous` 再比较。
    `resolveRogueMandatoryVictory()` 也在段号变化时补上重抽
- [x] **路线节点改为「每走完一个节点整批刷新」**（试玩反馈：「节点刷新是每过一个节点就要刷新」，
  已用 `ask_user` 确认需求方要的就是这个行为）
  - `RogueTurnManager` 抽出 `generatePlan(int)`（开段与刷新共用同一套生成规则），新增 `refreshRoute()`：
    按当前段号与剧情线 / 神兽状态重抽一批节点替换旧列表，**AP、段号、阶段、金币与剧情线标记都不重置**
  - `GameSession#refreshRogueRoute()` 暴露给控制器；`RogueTurnManager#resolveNode()`（非战斗节点）也补了刷新
  - `MainController#finishNodeStep()` 改为 `finishNodeStep(boolean refreshRoute)`：
    **刷新必须发生在 `advanceRogueNode()` 之前**——否则 AP 归零时旧列表里的 0 点节点（免单野外 / 特殊事件）
    会让 `RunData#hasSelectableOption()` 仍为 true，道馆永远触发不出来
  - 必然节点路径传 `false`：此时列表已由 `enterSegment()` / `enterPhase()` 重新生成，再刷一次属于覆盖新列表
- [x] 单测：`RogueTurnManagerTest` 26 → **29 例**，新增刷新相关 3 例
