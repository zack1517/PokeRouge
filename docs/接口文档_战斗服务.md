## 1. 概述

本模块把「回合制战斗逻辑」从界面/控制器中独立出来，对外暴露一个稳定接口
`BattleService`，供主界面、战斗界面等调用方使用。调用方只依赖接口，具体结算规则由
实现类 `BattleEngine` 承担，实例统一由静态工厂 `BattleServices` 创建。

设计目标：

- 战斗规则（伤害、速度先后手、捕捉、逃跑、天气与场地）与 UI 完全解耦；
- **战斗模块只消费数据**：技能、种族、野生池等一切数据经只读端口 `BattleDataPort` 由外部
  数据模块注入，模块内不内建任何数据、也不依赖具体数据源（见 §11）；
- **战斗模块只做演算与结算**：「遇到谁、几级」等遭遇生成属流程/组装层职责，不在本模块内
  （见 §12）；模块内不出现 `Math.random()`，随机源一律可注入；**经验增加、升级、学招、
  进化**同样不属于本模块，击倒与获胜时申报给外部成长端口 `BattleGrowthPort`，由成长模块
  自行判定（见 §13）；
- 调用方不直接依赖具体实现类，便于测试注入随机源、数据端口与成长端口、后续替换实现；
- 以「每回合新增日志行」作为行动结果的统一反馈通道。

## 2. 模块结构

```
org.example.battle
├── BattleService.java    [接口] 战斗服务契约（本文档主体）
├── BattleServices.java   [工厂] 创建战斗实例（静态）
├── BattleDataPort.java   [端口] 只读数据端口：技能/种族/野生池/按种族生成个体（见 §11）
├── BattleDataPorts.java  [端口] 端口工厂与空实现（BattleDataPorts.none()）
├── BattleGrowthPort.java [端口] 成长申报端口：结算后交由外部成长模块判定（见 §13）
├── BattleEvent.java      [模型] 战斗演出事件（动画数据源，见 §16）
└── BattleEngine.java     [实现] 回合制对战引擎（默认/唯一实现）
```

> **数据零依赖**：`org.example.battle` 包内不出现任何数据文件、内建数据表或对数据模块
> （如 `org.example.data`）的依赖；引擎所需的技能与种族一律经 `BattleDataPort` 查询。
>
> **无遭遇生成、无成长规则**：本包不包含「野生遭遇生成」逻辑（v1.7 起迁至
> `org.example.integration.WildEncounter`），也不在引擎内实现经验曲线、习得表或进化规则
> （v1.9 起交由外部成长模块，见 §13）；包内不出现 `Math.random()`，所有随机源均为可注入的
> `java.util.Random`。

依赖的模型类型（均位于 `org.example.model`）：`Player`、`Pokemon`、`MoveSlot`、
`Item`、`Bag`、`Trainer`（训练师轮战的敌方队伍，见 §3.4），以及天气/场地系统相关枚举
`Weather`、`Terrain`、`MoveEffect`（见 §7）。

## 3. 接口：`BattleService`

全限定名：`org.example.battle.BattleService`

### 3.1 嵌套枚举 `Status`（战斗状态）

| 常量         | 含义                     | 触发场景                         |
|--------------|--------------------------|----------------------------------|
| `ONGOING`    | 进行中                   | 战斗尚未结束，可继续行动         |
| `PLAYER_WIN` | 玩家获胜                 | 野生精灵倒下（野生遭遇），或训练师整队精灵全部倒下（训练师轮战）；随后向成长模块申报结算（§13） |
| `PLAYER_LOSE`| 玩家战败                 | 队伍全部倒下且无精灵可替换（有健康精灵时先进入补位等待，见 §3.3a） |
| `FLED`       | 逃跑成功                 | `tryRun()` 成功（仅野生遭遇）   |
| `CAUGHT`     | 捕捉成功                 | 精灵球捕捉成功并加入玩家队伍（仅野生遭遇） |

### 3.2 回合行动方法

所有行动方法均**要求战斗进行中**（`status == ONGOING`）**且不处于补位等待**
（`isAwaitingReplacement() == false`），否则抛出 `IllegalStateException`。
返回值为**本回合新产生**的日志行（非全量日志）。

> v1.14 起：己方出战精灵倒下而队伍仍有健康精灵时，战斗仍为 `ONGOING`，但一切行动方法都会被
> 拒绝（提示「需要先选择上场的精灵」），必须先调用 `chooseReplacement(int)` 补位（见 §3.3a）。
> 这是**引擎侧硬约束**，任何调用方（JavaFX 界面 / 控制台 demo / 测试）都无法绕过。

#### `List<String> useMove(MoveSlot slot)`

玩家选择技能攻击。敌方（野生精灵，或训练师当前出战精灵）自动选择可用技能；双方都行动时
按速度决定先后手，速度相同则随机。

> 先制说明：`Move` 数据契约已含先制度 `priority`（越大越先出手，0 为普通技能），
> 当前引擎尚未消费该字段，先后手仍按速度判定；先制排序留待后续扩展。

| 项     | 说明 |
|--------|------|
| 参数   | `slot`：当前出战精灵的技能槽；`null` / PP 耗尽 / 非当前精灵的槽位会自动退回当前精灵第一个可用技能；完全无可用技能则本回合不行动 |
| 返回   | 本回合新增日志行 |
| 副作用 | 消耗 PP；**变化类技能**若携带天气/场地效果（`MoveEffect`）则改为开启/重置对应天气/场地（见 §7），不造成伤害；普通技能命中则计算伤害；若击倒野生精灵进入 `PLAYER_WIN`（训练师轮战则换下一只，整队全倒才进入 `PLAYER_WIN`），玩家精灵倒下则进入**等待补位**状态或 `PLAYER_LOSE`（见 §3.3a） |

#### `List<String> useItem(Item item, int partyIndex)`

使用道具于**指定队伍精灵**。按道具类别分流：`HEAL` 回复目标精灵 HP；`CURE` 解除目标精灵
异常状态；`POKE_BALL` 尝试捕捉野生精灵（**与目标无关**，始终投向敌方；捕捉公式：血量越低、
捕获率越高、球倍率越大越易成功，目标陷入睡眠/麻痹时再 ×2，必定捕捉球直接成功）。

| 项     | 说明 |
|--------|------|
| 参数   | `item`：要使用的道具；`null` 或背包中数量不足则不行动。`partyIndex`：目标精灵在玩家队伍中的下标 |
| 返回   | 本回合新增日志行 |
| 目标   | `partyIndex` 越界 → 追加「没有可以使用的目标。」并**不消耗道具、不消耗回合**；**回复道具对已倒下精灵无效**（不能以此复活，原版行为），追加提示且不消耗；解除道具对已倒下精灵**仍然有效**（倒下时异常状态保留） |
| 副作用 | 回复/解除道具仅在使用成功（确有效果）时消耗背包数量；精灵球使用后无论成败都会消耗；使用后若战斗未结束，敌方行动一次。**训练师轮战不可捕捉**：对训练师投球会被拒绝，只追加一条提示日志，**精灵球不消耗、也不消耗回合** |

> `useItem(Item item)` 是作用域为**当前出战精灵**的便捷重载（`default` 方法，等价于
> `useItem(item, 出战精灵下标)`）；既有调用点无需改动。

#### `List<String> useItem(Item item)`

`useItem(item, partyIndex)` 的便捷重载：作用于**当前出战精灵**。参数与副作用同上；若当前出战
精灵满血（`HEAL`）或无可解除异常（`CURE`），则追加提示并**不消耗道具、不消耗回合**。

#### `List<String> tryRun()`

尝试逃跑。成功率 = `0.35 + 0.6 × (我方速度 / (我方速度 + 敌方速度))`，
速度越接近成功率越低（约 0.65），远超时接近 0.95。

| 项     | 说明 |
|--------|------|
| 返回   | 本回合新增日志行 |
| 副作用 | 成功 → `FLED`；失败 → 敌方行动一次。**训练师轮战不可逃跑**：只追加「无法逃跑」提示日志，不消耗回合 |

#### `List<String> switchActive(int partyIndex)`

消耗本回合行动切换出战精灵，收换完成后敌方行动一次。

| 项     | 说明 |
|--------|------|
| 参数   | `partyIndex`：玩家队伍中目标精灵下标 |
| 返回   | 本回合新增日志行 |
| 副作用 | 目标与当前相同 / 下标非法 / 目标不存在时不行动（不消耗回合）。**补位等待期间本方法会被拒绝**（抛 `IllegalStateException`），此情形请改用 `chooseReplacement(int)` |

### 3.3 状态查询方法

| 方法签名 | 返回 | 说明 |
|----------|------|------|
| `Player getPlayer()` | 玩家 | 本场战斗的玩家（含队伍与背包） |
| `Pokemon getWild()` | 野生精灵 | 本场战斗的野生精灵；**训练师轮战中为 `null`** |
| `Trainer getTrainer()` | 训练师 | 本场战斗的训练师；**野生遭遇中为 `null`** |
| `Pokemon foeActive()` | 敌方出战精灵 | 野生遭遇为野生精灵，训练师轮战为训练师当前出战精灵；界面应统一用它渲染敌方面板 |
| `Pokemon playerActive()` | 出战精灵 | 玩家当前出战精灵；**等待补位期间为刚倒下的那只**（补位后即为新上场精灵），非 `null` |
| `Status getStatus()` | 战斗状态 | 见 3.1 |
| `boolean isOngoing()` | 是否进行中 | 等价 `getStatus() == Status.ONGOING`（**等待补位时仍为 `true`**） |
| `boolean isAwaitingReplacement()` | 是否等待补位 | 己方出战精灵倒下且队伍仍有健康精灵时为 `true`；此时界面应改为展示队伍选择面板（见 §3.3a） |
| `List<String> getLog()` | 日志 | 完整战斗日志（只读，不可修改） |
| `List<BattleEvent> drainEvents()` | 演出事件 | **取走**自上一条行动方法调用以来累积的演出事件并清空队列（见 §16）；同一事件只投递一次 |
| `Bag getBag()` | 背包 | 便捷转发，等价 `getPlayer().getBag()` |
| `Weather getWeather()` | 天气 | 当前天气；无天气为 `Weather.NONE`，由天气类变化技能开启（见 §7） |
| `Terrain getTerrain()` | 场地 | 当前场地；无场地为 `Terrain.NONE`，由场地类变化技能开启（见 §7） |
| `List<String> chooseReplacement(int partyIndex)` | 本回合新增日志行 | 己方出战精灵倒下后**由玩家选出下一只上场精灵**；不消耗回合、敌方不行动（见 §3.3a） |

#### 3.3a 己方倒下后的补位（v1.14）

己方出战精灵倒下时，引擎**不再自动换宠**：

| 情形 | 引擎行为 |
|------|----------|
| 队伍仍有健康精灵 | `isOngoing()` 仍为 `true`，`isAwaitingReplacement()` 变为 `true`，日志追加「请选择接下来上场的精灵！」；**所有回合行动方法抛 `IllegalStateException`**，直到玩家调用 `chooseReplacement(int)` |
| 队伍已无健康精灵 | 直接 `PLAYER_LOSE`（`isAwaitingReplacement()` 保持 `false`） |

`chooseReplacement(int partyIndex)` 的语义：

| 项 | 说明 |
|----|------|
| 参数 | `partyIndex`：玩家队伍中目标精灵下标 |
| 成功 | 目标转为出战精灵，追加「你派出了 <名>！」，上场精灵 `clearVolatileState()` 后**从中立状态开始**，压入一条 `SEND_OUT`（玩家方）演出事件；`isAwaitingReplacement()` 恢复 `false`，可继续正常行动 |
| 不消耗回合 | 补位本身不是回合行动，敌方**不会**因此行动（区别于 `switchActive`） |
| 非法目标 | 目标为已倒下精灵 / 下标越界时追加「倒下的精灵不能上场，请选择其他精灵。」，**状态不变**（仍等待，可重试） |
| 异常 | 非等待状态（`isAwaitingReplacement() == false`）调用时抛 `IllegalStateException` |

> 界面接线：`BattleController.render()` 在 `isOngoing()` 分支内优先判断
> `isAwaitingReplacement()`，是则弹出**不可返回**的队伍选择面板
> （`BattleView.showReplacementMenu`），选中后调用 `chooseReplacement(idx)` 再重新渲染。
> 控制台 demo（`BattleConsole`）在主循环中以 `doReplacement(...)` 对应处理。

### 3.4 训练师轮战（敌方持有一整支队伍）

敌方由 `org.example.model.Trainer` 描述（队伍上限 6 只，与 `Player` 同一套队伍
契约：首个加入者自动成为出战精灵）。**注意**：`Trainer`/`Player` 模型层的
`switchToNextHealthy()` 仍保留「自动切换下一只健康精灵」的能力，但 v1.14 起引擎对
**玩家方**不再自动调用它，改为挂起等待玩家补位（§3.3a）；对**训练师方**仍在 `resolveRoundEnd`
中自动调用。判定与野生遭遇的区别：

| 项 | 野生遭遇 | 训练师轮战 |
|----|----------|------------|
| 敌方来源 | `getWild()` | `getTrainer()`（`getWild()` 为 `null`） |
| 当前敌方精灵 | `foeActive()` = 野生精灵 | `foeActive()` = `trainer.getActive()` |
| 结束条件 | **野生精灵倒下**即 `PLAYER_WIN` | **敌方整队精灵全部倒下**才 `PLAYER_WIN` |
| 玩家战败 | 己方整队全部倒下且无精灵可替换 → `PLAYER_LOSE` | 同左 |
| 己方倒下后 | 挂起等待玩家 `chooseReplacement(int)` 补位（§3.3a） | 同左（与敌方无关） |
| 敌方倒下后 | 战斗结束 | 自动派出下一只健康精灵（训练师不会主动换宠，换宠当回合新精灵不行动） |
| 逃跑 | 可尝试 | 不可（`tryRun()` 只记日志，不消耗回合） |
| 捕捉 | 可投球捕捉 | 不可（投球不消耗道具、不消耗回合） |
| 天气/场地、技能 PP | 整场持续 | 整场持续（换宠不重置） |
| 胜利经验 | **每击倒一只即时申报一次**（野生精灵倒下 / 训练师每只倒下各一次） | 同左：**每只对手倒下即时申报**，不等整场结束（§13） |

> 判定顺序：同一回合敌方出战精灵倒下时，先由训练师派出下一只；派不出（整队全倒）则立即
> `PLAYER_WIN`，随后才处理玩家精灵倒下后的补位挂起/`PLAYER_LOSE`。

### 3.5 学习抉择（技能栏已满）

| 方法签名 | 返回 | 说明 |
|----------|------|------|
| `List<LearnChoice> pendingLearnChoices()` | 待抉择队列 | 成长模块申报结算时挂起的「到级学招但技能栏已满」项；空表示无待抉择。自 v1.11 起经验**逐只即时结算**，故该队列可能**在战斗进行中非空**（不再只在战斗结束时） |
| `List<String> decideLearn(int forgetSlotIndex)` | 本回合新增日志行 | 对队首抉择作出决定：`forgetSlotIndex >= 0` 且合法则遗忘该槽位并学会新技能；`-1` 或越界则放弃学习。队列为空时抛 `IllegalStateException` |

嵌套类型：`BattleService.LearnChoice`（`record(Pokemon pokemon, Move move)`）。

> 队列由引擎管理（出入队、空队列异常），**判定与文本**由成长模块给出（见 §13）：
> 引擎只把玩家的 `forgetSlotIndex` 转发给 `BattleGrowthPort#resolveLearn`，并追加返回的日志行。

## 4. 工厂：`BattleServices`

> 种族 `randomWild`）自 v1.7 起移出本模块，见 `org.example.integration.WildEncounter`
> （§12）。

## 5. 使用示例

```java
// 0) 组装层准备端口（外部模块实现，战斗模块不关心其内部）
BattleDataPort dataPort = new GameDataBattleDataPort();                // 见 §11
BattleGrowthPort growthPort = PokemonBattleAdapter.battleGrowthPort(dataPort); // 见 §13
// 自定义成长模块亦可自行实现 BattleGrowthPort 并在组装层替换

// 1) 组装玩家（队伍 + 背包），进入随机遭遇
Player player = ...;                       // 需有存活出战精灵
int level = WildEncounter.levelAround(player.getActive().getLevel());        // 组装/流程侧
Optional<Pokemon> wild = WildEncounter.randomWild(level, dataPort);          // 组装/流程侧
if (wild.isEmpty()) return;

// 2) 创建战斗服务（返回的是接口类型），注入数据端口与成长端口
BattleService battle = BattleServices.newBattle(player, wild.get(), dataPort, growthPort);

// 3) 回合驱动：进行中则让玩家选择一个行动
while (battle.isOngoing()) {
    if (battle.isAwaitingReplacement()) {        // 己方倒下：必须由玩家选出下一只
        battle.chooseReplacement(askReplacementIndex(battle.getPlayer().getParty()));
        continue;                                // 补位不消耗回合，敌方不会行动
    }
    List<String> lines = battle.useMove(currentMoveSlot); // 技能 / useItem(item, partyIndex) / tryRun / switchActive
    for (String line : lines) logView.append(line);
    // 技能栏已满时成长模块会挂起学习抉择：取队首项并让玩家选择遗忘槽位（-1 = 放弃学习）
    if (!battle.pendingLearnChoices().isEmpty()) {
        int slot = askForgetSlot();                       // 玩家选择
        for (String line : battle.decideLearn(slot)) logView.append(line);
    }
}

// 4) 依据结果状态收尾
switch (battle.getStatus()) {
    case PLAYER_WIN -> onWin(battle.getPlayer());   // 成长已在每次击倒时由成长模块即时完成
    case PLAYER_LOSE -> onLose();
    case FLED       -> backToMap();
    case CAUGHT     -> onCaught(battle.getWild());
    case ONGOING    -> { /* 不应出现 */ }
}
```

训练师轮战（敌方整队，某一方全灭才结束）：

```java
// 训练师队伍（可从外部数据/流程系统按节点难度组装）
Trainer trainer = new Trainer("路人训练师");
trainer.addPokemon(level20Mon);
trainer.addPokemon(level22Mon);

BattleService battle = BattleServices.newTrainerBattle(player, trainer, dataPort, growthPort);

// 界面渲染统一取 foeActive()：换宠后自动跟随
render(battle.playerActive(), battle.foeActive());

while (battle.isOngoing()) {
    if (battle.isAwaitingReplacement()) {                    // 己方倒下：先补位
        battle.chooseReplacement(askReplacementIndex(battle.getPlayer().getParty()));
        continue;
    }
    // 训练师战无逃跑/捕捉：tryRun()、对训练师投球只返回提示日志且不消耗回合
    battle.useMove(slot);
    render(battle.playerActive(), battle.foeActive());
}
// battle.getTrainer().isPartyAllFainted() == true 时为 PLAYER_WIN
```

## 6. 回合驱动流程（状态机）

```
        ┌─────────────────────────────────────────────────────┐
        │  ONGOING  (玩家每回合选择 技能/道具/逃跑/换宠)       │
        │  ┌───────────────────────────────────────────────┐  │
        │  │ 引擎内部结算：                                 │  │
        │  │   先后手 → 伤害 → 胜负 → 申报成长（端口）      │  │
        │  │   回合末：结算天气/场地效果并推进剩余回合       │  │
        │  └───────────────────────────────────────────────┘  │
        │  ┌───────────────────────────────────────────────┐  │
        │  │ 补位等待子状态（己方倒下且队伍仍有健康精灵）    │  │
        │  │   只接受 chooseReplacement(int)                │  │
        │  │   其余行动方法一律抛 IllegalStateException     │  │
        │  └───────────────────────────────────────────────┘  │
        └──────────┬──────────────┬───────────────┬──────────┘
                   ▼              ▼               ▼
              PLAYER_WIN     PLAYER_LOSE     FLED / CAUGHT
```

- 行动期间精灵倒下时：
  - **己方**：队伍仍有健康精灵 → 进入**补位等待**（`isAwaitingReplacement() == true`，
    `status` 仍为 `ONGOING`，日志提示「请选择接下来上场的精灵！」），此时除
    `chooseReplacement(int)` 外的所有行动方法抛 `IllegalStateException`；补位完成后回到
    正常 `ONGOING`。队伍已无健康精灵 → `PLAYER_LOSE`；
  - **敌方**：野生遭遇直接 `PLAYER_WIN`；训练师轮战自动派出下一只健康精灵；
- **训练师轮战**：敌方当前出战精灵倒下后自动派下一只健康精灵（换宠当回合新精灵不行动），
  敌方整队精灵全部倒下才 `PLAYER_WIN`；玩家整队全倒才 `PLAYER_LOSE`；不可逃跑/捕捉（§3.4）；
- 每击倒一只对手就把「参战且未倒下的己方精灵」与「刚被击倒的那一只」申报给成长端口（§13）：
  引擎不计算经验、不判定升级/学招/进化，只把成长模块返回的日志行追加到战斗日志；训练师轮战
  **逐只申报**、不等整场结束，整场以 `PLAYER_WIN` 收尾时另经 `onBattleWon` 申报一次；
- 每回合行动结束后（双方仍站场时）引擎结算天气/场地回合末效果，并推进
  天气/场地剩余回合（见 §7）。

## 7. 天气与场地

战斗双方共享同一片天气（`Weather`）与场地（`Terrain`），由携带对应效果的
**变化类技能**开启，持续固定回合后自然消退，持续期间影响招式威力和回合末效果。

### 7.1 开启与持续

- **开启方式**：使用带效果的变化类技能（如「大晴天」「青草场地」）。普通物理/特殊
  技能不影响天气与场地。效果枚举 `MoveEffect`（`org.example.model`）把技能映射到
  对应 `Weather` / `Terrain`。
- **持续回合**：`Weather.DURATION_TURNS` / `Terrain.DURATION_TURNS` 均为 5 回合
  （含开启当回合）。每回合末引擎推进计数，归零后天气/场地消退并写入结束消息
  （如「沙暴平息了。」「青草场地的效果消失了。」）。
- **覆盖与重置**：再次开启同类天气/场地会重置剩余回合并提示「持续回合重置了！」；
  开启不同类的天气/场地则替换前一类。天气与场地相互独立，可同时生效。

### 7.2 效果明细

| 状态 | 开启技能效果（`MoveEffect`） | 招式威力倍率 | 回合末效果 |
|------|------------------------------|--------------|------------|
| `Weather.SUNNY` 大晴天 | `SUNNY_DAY` | 火系 ×1.5 | — |
| `Weather.RAIN` 下雨 | `RAIN_DANCE` | 水系 ×1.5 | — |
| `Weather.SANDSTORM` 沙暴 | `SANDSTORM` | — | 非岩石/地面系扣最大 HP 的 1/16 |
| `Weather.HAIL` 冰雹 | `HAIL` | — | 非冰系扣最大 HP 的 1/16 |
| `Terrain.ELECTRIC` 电气场地 | `ELECTRIC_TERRAIN` | 电系 ×1.3 | — |
| `Terrain.GRASSY` 青草场地 | `GRASSY_TERRAIN` | 草系 ×1.3 | 场上非飞行系精灵回复最大 HP 的 1/16 |
| `Terrain.MISTY` 薄雾场地 | `MISTY_TERRAIN` | 龙系 ×0.5 | — |
| `Terrain.PSYCHIC` 精神场地 | `PSYCHIC_TERRAIN` | 超能力系 ×1.3 | — |

规则细节：

- 天气与场地的倍率**可叠加**（伤害计算时按 天气倍率 × 场地倍率 连乘）；
- 回合末效果（沙暴/冰雹扣血、青草回复）仅在**双方都仍站场**时结算；满血精灵不会
  产生回血日志；免疫精灵不产生扣血日志；
- 变化类技能同样消耗 PP 与整回合行动，规则与伤害技能一致（只是不造成伤害）；
- 战斗结束（胜负/逃跑/捕获）后天气/场地不残留到下一场。

### 7.3 界面展示

UI 层通过 `getWeather()` / `getTerrain()` 在每次行动后刷新状态条，展示
`Weather.getDisplayName()` / `Terrain.getDisplayName()`（如「大晴天」「青草场地」）。

## 8. 实现与扩展约束

- 唯一实现 `BattleEngine`（同包），构造时校验玩家出战精灵与敌方（野生精灵或训练师出战精灵）均有效；
- 调用方应通过 `BattleServices` 获取实例，禁止 `new BattleEngine(...)`；
- 若需新增自定义实现，实现 `BattleService` 即可，UI 层无需改动；
- 界面渲染敌方面板一律取 `foeActive()`，不要直接读 `getWild()`（训练师轮战中为 `null`）。

### 8.1 `Move` 数据契约对齐（v1.2）

为适配「宝可梦、技能、队伍接口.md」（v1.0，待组长评审），`org.example.model.Move`
数据契约调整如下（本次仅数据模型对齐，不改变引擎行为）：

| 字段 | 语义 |
|------|------|
| `priority`（新增） | 先制度，数值越大越先出手；0 为普通技能。`getPriority()` 读取。当前引擎按速度先后手，暂未启用先制排序 |
| `accuracy` | 命中率 0~100；**-1 表示必中**（负值在构造时归一为 -1，正值 clamp 至 100）。当前引擎恒命中，未做命中判定 |

构造重载保持向后兼容：原 7/8 参构造委托至新完整构造（`priority=0`），
既有 `GameData` 技能注册代码无需改动。

## 10. 异常状态（v1.5）

参照原版宝可梦，把**异常状态**接入 `BattleEngine` 结算。规则集中在
`org.example.model.StatusCondition`，模型状态由 `Pokemon` 维护，界面由 `BattleView` 展示。

### 10.1 分类与效果

| 枚举 | 显示名 | 类别 | 效果 | 免疫属性 |
|------|--------|------|------|----------|
| `PARALYSIS` | 麻痹 | 主要（可保留） | 实际速度 ×0.5；每次行动有 **25%** 概率无法行动（不消耗 PP） | 电 |
| `POISON` | 中毒 | 主要 | 回合末损失 **1/8** 最大 HP | 毒 |
| `BADLY_POISON` | 剧毒 | 主要 | 回合末损失 `max(1, 计数)/16` 最大 HP，计数逐回合 +1（起始 1） | 毒 |
| `BURN` | 灼伤 | 主要 | 回合末损失 **1/16** 最大 HP；**物理**攻击 ×0.5 | 火 |
| `SLEEP` | 睡眠 | 主要 | 无法行动，随机 **2~5** 回合后自动醒来（醒来当回合即可行动） | — |
| `FREEZE` | 冰冻 | 主要 | 无法行动，每次行动有 **20%** 概率自行解冻（解冻当回合即可行动） | 冰 |
| `CONFUSION` | 混乱 | 挥发性（换宠/倒下即清） | 每次行动有 **33%** 概率**自伤**（威力 40 的无属性物理伤害）；随机 **2~5** 回合后解除 | — |
| `FAINTED` | 倒下 | 特殊 | 不可行动（由 `takeDamage` 自动置位） | — |
| `NONE` | — | — | 无异常状态 | — |

- **主要异常**（`isMajor()`）同一时刻只能存在一种；**挥发性异常**（`isVolatile()`，即混乱）
  可与主要异常**共存**，但不可叠加。
- `majorStatuses()` 返回全部 6 种主要异常的不可变列表（供「万灵药」等判定使用）。
- 常量：`BADLY_POISON_START=1`、`SLEEP_MIN_TURNS=2`、`SLEEP_MAX_TURNS=5`、
  `CONFUSION_MIN_TURNS=2`、`CONFUSION_MAX_TURNS=5`、`PARALYSIS_SKIP_CHANCE=0.25`、
  `CONFUSION_SELF_HIT_CHANCE=0.33`、`FREEZE_THAW_CHANCE=0.2`、`CONFUSION_SELF_HIT_POWER=40`。

### 10.2 规则查询 API（`StatusCondition`）

| 方法 | 说明 |
|------|------|
| `isMajor()` / `isVolatile()` / `preventsAction()` | 分类与「是否彻底无法行动」（睡眠/冰冻/倒下为 true，麻痹为 false） |
| `speedMultiplier()` / `attackMultiplier()` | 实际速度/物攻倍率（麻痹 0.5；灼伤 0.5） |
| `residualDamageRatio(int badlyPoisonCounter)` | 回合末持续伤害占最大 HP 的比例（0 表示无伤害） |
| `residualMessage(int badlyPoisonCounter)` | 持续伤害日志用的状态名（无伤害时为空串） |
| `canApply(Pokemon target)` | 是否可施加：**属性免疫 > 已混乱 > 已有主要异常** 依次判定 |
| `immunityType()` | 免疫该异常的属性（无则 `null`） |
| `parse(String)` / `getDisplayName()` | 按英文名或中文名解析（非法/空白/`null` 归一为 `NONE`）；显示名 |

### 10.3 `Pokemon` 状态契约

`Pokemon` 维护 `status`（主要异常）、`confusionTurns`、`sleepTurns`、`badlyPoisonCounter`，
并提供：

| 方法 | 说明 |
|------|------|
| `getStatus()` / `setStatus(StatusCondition)` | 读取/直接设置主要异常（混乱走混乱计数；睡眠取最短；剧毒计数重置为 1） |
| `tryApplyStatus(StatusCondition, int turns)` | 施加异常（含回合数），成功返回 `true`、失败返回 `false` |
| `cureStatus()` | 解除主要异常，返回被解除的状态（无则 `NONE`） |
| `isConfused()` / `getConfusionTurns()` / `applyConfusion(int)` / `clearConfusion()` | 混乱的查询/施加/清除（`clearConfusion()` 返回此前是否存在混乱） |
| `clearAllStatus()` | 清除全部异常状态（含混乱、睡眠回合数、剧毒计数） |
| `getSleepTurns()` / `tickSleep()` | 睡眠剩余回合数；回合推进（`true`=仍在睡，`false`=本回合醒来且状态已清） |
| `tickConfusion()` / `getBadlyPoisonCounter()` / `increaseBadlyPoisonCounter()` | 混乱回合推进；剧毒计数读取与递增 |
| `effectiveSpeed()` / `effectiveAttack()` | 计入异常倍率后的**实际**速度/物攻（`BattleEngine` 先手判定、逃跑判定、伤害计算一律使用它） |
| `fullHeal()` / `fullRestore()` | 完全回复，内部调用 `clearAllStatus()` |

倒下（`takeDamage` 使 HP 归零）时自动清除自身混乱。

### 10.4 引擎结算流程（`BattleEngine`）

1. **先后手**：按 `effectiveSpeed()` 比较；同速再用随机数决定（`firstMover`）。
2. **玩家行动**（`playerAct`）：先做 `canAct` 判定，**通过后**才 `MoveSlot.use()`
   ——因为 `MoveSlot.use()` 在 PP 耗尽时返回 `false` 且不消耗 PP，判定必须前置。
3. **`canAct(self)`** 判定顺序：`睡眠`（`tickSleep`）→ `冰冻`（20% 解冻）→ `麻痹`（25% 略过）
   → `混乱`（33% 自伤，威力 40）。返回 `false` 表示本回合无法行动。
4. **命中后施加异常**（`tryInflict`，`executeMove`/`performAttack` 中调用）：
   `condition.canApply(defender)` → 概率判定（`nextInt(100) >= chance` 则不触发，即
   `inflictionChance=N` 时为 `N%`）→ 随机回合数（仅睡眠/混乱，2~5）→ `tryApplyStatus`。
   变化类技能只要带 `inflicts` 也会进入结算（`MoveEffect.NONE` 不再提前跳过）。
5. **回合末**（`applyFieldEndEffects` → `statusEndTurn`）：先结算天气/场地，再按
   `residualDamageRatio` 扣血（中毒/剧毒/灼伤），随后剧毒计数 +1。麻痹/睡眠/冰冻/混乱**无**回合末伤害。
6. **换宠**（`switchActive`）：收回的精灵 `clearConfusion()` 并提示「混乱解除了！」；
   主要异常**保留**。
7. **敌方行动**（`foeTurn`）同样先做 `canAct` 判定。
8. `finishRound` 在 `Status.ONGOING` 时才推进回合，避免战斗结束后继续结算。

## 11. 数据端口：`BattleDataPort`（v1.6）

### 11.1 定位

战斗模块**只消费数据、不拥有数据**。引擎运行期需要的外部数据只有四类，统一抽象为只读端口：

| 需求 | 端口方法 | 使用场景 |
|------|----------|----------|
| 按 id 查技能 | `Move findMove(String moveId)` | 外部成长模块的到级学招（`GrowthService#learnAt`，见 §13） |
| 按 id 查种族 | `Species findSpecies(String speciesId)` | 外部成长模块的进化（`GrowthService#evolve`） |
| 野生遭遇候选池 | `List<String> wildSpeciesPool()` | 组装/流程侧随机遭遇（`WildEncounter.randomWild`） |
| 按种族生成个体 | `Optional<Pokemon> createPokemon(String speciesId, int level)` | 组装/流程侧随机遭遇（`WildEncounter.randomWild`） |

全限定名：`org.example.battle.BattleDataPort`（接口）。

> 查不到即返回 `null`（`findMove`/`findSpecies`）或 `Optional.empty()`（`createPokemon`），
> 调用方（成长模块 / 遭遇生成）据此**静默跳过**对应功能，不抛异常。
>
> **v1.9 注**：引擎本体已不再查询本端口（成长判定外移至 §13），端口仍是战斗相关外部数据的
> **统一入口**，供外部成长模块与遭遇生成共用。

### 11.2 空实现

`org.example.battle.BattleDataPorts` 提供 `BattleDataPorts.none()`：所有查询返回「查不到」，
用于纯规则测试或不接数据源运行的场景。**未注入端口的所有工厂/构造器入口都使用它**，
因此既有调用点（`BattleServices.newBattle(player, wild)` 等）行为保持不变：战斗规则照常运行，
依赖数据的「随机野生遭遇」（§12）与外部成长模块的「到级学招 / 进化」（§13）降级为无操作。

### 11.3 默认实现

`BattleDataPort#createPokemon` 提供默认实现：按 `Species#getMoveIds()` 取种族首批技能
（最多 `Pokemon.MAX_MOVES` 个，跳过端口查不到的技能）生成个体。数据模块可覆盖此方法
（例如按等级筛选可学技能）。

> **已知取舍**：端口本应只描述「需求」，该默认实现却含少量「按种族首批技能生成」的
> **生成策略**。保留它换取实现方免写样板代码；若后续生成规则复杂化，应把策略整体
> 移入数据侧实现，让端口退回纯声明。

### 11.4 外部实现与注入

数据模块通过**适配器**实现端口，把自身数据源暴露给战斗模块；组装层负责创建并注入：

- `org.example.data.GameDataBattleDataPort`：把数据注册表 `GameData` 适配为端口；
- `org.example.integration.PokemonBattleAdapter#battleDataPort()`：组装层统一入口
  （`MainController` 经此注入战斗引擎与成长模块）；
- `org.example.demo.BattleConsole`：演示入口自行构造并注入。

```java
// 组装层（控制器 / 演示入口）
BattleDataPort dataPort = PokemonBattleAdapter.battleDataPort();
BattleGrowthPort growthPort = PokemonBattleAdapter.battleGrowthPort(dataPort);   // 见 §13
BattleService battle = BattleServices.newBattle(player, wild, dataPort, growthPort);
```

### 11.5 解耦约束

- `org.example.battle` 包内**不出现**数据文件、内建数据表，也不引用数据模块
  （如 `org.example.data`）；所有数据一律经端口获取；
- 新增外部数据源（CSV、网络、另一套宝可梦系统）时无需改动战斗模块，只要实现端口并在
  组装层替换即可；
- 道具不属于数据端口：`useItem(Item, int)` 只消费**调用方传入的实例**，道具来源由组装层决定。

### 11.6 测试覆盖

`src/test/java/org/example/battle/BattleDataPortTest.java`（**6** 个用例）覆盖：
空端口不提供任何数据、升级学招经成长模块查询技能（注入成长端口 / 未注入成长端口）、
进化经成长模块查询种族（注入 / 未注入）、端口默认个体生成的技能截断与查不到种族返回空。

| `int levelAround(int playerLevel)` | 建议等级 | 在 `[level-2, level+2]` 内随机，最低 `MIN_LEVEL`（2） |
| `int levelAround(int playerLevel, Random random)` | 建议等级 | 同上，随机源可注入 |
| `Optional<Pokemon> randomWild(int aroundLevel, BattleDataPort dataPort)` | 野生精灵 | 从端口野生池随机挑选并经端口生成个体 |
| `Optional<Pokemon> randomWild(int aroundLevel, BattleDataPort dataPort, Random random)` | 野生精灵 | 同上，随机源可注入 |

常量：`LEVEL_SPREAD = 2`（等级浮动半宽）、`MIN_LEVEL = 2`（等级下限）。

### 12.3 内聚性收益

- 战斗模块内**不再出现 `Math.random()`**：包内所有随机源均为可注入的 `java.util.Random`
  （引擎构造器参数），遭遇侧同理，测试可完全复现；
- `BattleServices` 收敛为**纯工厂**（仅 12 个 `newBattle` / `newTrainerBattle` 重载，含 v1.9
  新增的 4 个成长端口重载）；
- 遭遇生成只依赖 `BattleDataPort` 与 `Random` 两个抽象，与战斗模块**同向解耦**。

### 12.4 调用点

- `org.example.controller.MainController#startRandomBattle()`：`WildEncounter.levelAround(...)`
  → `PokemonBattleAdapter.createWildPokemon(level)` → `BattleServices.newBattle(...)`，
  并注入 `PokemonBattleAdapter.battleDataPort()` 与 `battleGrowthPort(dataPort)`；
- `org.example.demo.BattleConsole#oneWildBattle()`：
  `WildEncounter.randomWild(WildEncounter.levelAround(top), BATTLE_DATA)`
  → `BattleServices.newBattle(player, wild, BATTLE_DATA, GROWTH)`。

`src/test/java/org/example/integration/WildEncounterTest.java`（**5** 个用例）覆盖：

## 13. 成长端口：`BattleGrowthPort`（v1.9）

### 13.1 定位

战斗模块**只做演算与结算**。胜利结算时不自行计算经验、不判定升级 / 学招 / 进化，而是把
「参战且未倒下的己方精灵」（`survivors`）与「被击败的对手」（`defeated`）**申报**给成长端口，
由外部成长模块自行判定一切，并把需要写入战斗日志的文本行返回。

| 需求 | 端口方法 | 说明 |
|------|----------|------|
| 击倒申报（v1.11 语义） | `Settlement settle(List<Pokemon> survivors, List<Pokemon> defeated)` | **每击倒一只对手调用一次**：`defeated` 恒为刚被击倒的那一只；返回日志行与挂起的学招抉择 |
| 获胜申报（v1.11） | `void onBattleWon(List<Pokemon> survivors)` | 整场战斗结束且 `PLAYER_WIN` 时**调用一次**（野生获胜 / 训练师全队倒下各一次）；`default` 空实现，供成长模块按**场次**做事（如累计图鉴对战次数） |
| 学招抉择执行 | `List<String> resolveLearn(BattleService.LearnChoice choice, int forgetSlotIndex)` | 引擎转发玩家的遗忘槽位选择（`-1` = 放弃学习） |
| 捕捉申报（v1.10） | `void onCaptured(String speciesId)` | 引擎在野生遭遇**捕捉成功**时调用；`default` 空实现，不实现即保持原行为 |

常量与嵌套类型：

| 名称 | 形态 | 说明 |
|------|------|------|
| `BattleGrowthPort.Settlement` | `record(log, pendingLearns)` | `List<String> log`（逐行追加到战斗日志）、`List<BattleService.LearnChoice> pendingLearns`（技能栏已满时挂起） |
| `BattleGrowthPort.none()` | 静态方法 | 空端口：`settle` 返回空 `Settlement`，`resolveLearn` 返回空列表，`onCaptured` 与 `onBattleWon` 为空操作 |

全限定名：`org.example.battle.BattleGrowthPort`（接口，契约放在引擎侧被跨模块共享）。

> `onCaptured` 与 `onBattleWon` 之所以是 `default`：战斗模块只负责判定「是否捕捉成功 / 战斗是否
> 获胜」并申报事实，**收益如何换算由成长模块决定**；`none()` 与既有第三方实现因此无需改动即兼容。
>
> **`settle` 的语义变化（v1.11）**：旧版是「整场结束后把整队被击败对手一次性申报，由成长模块
> 求和后发放」；新版改为「**每击倒一只就申报一次**」，成长模块**立即**结算该只的经验。收益差别：
> 中途倒下的己方精灵也能拿到已经击倒对手的经验，**战败不回收**；对战次数统计改由 `onBattleWon`
> 按场次进行，避免逐只申报把一场战斗重复计数。

### 13.2 引擎侧流程

```
每击倒一只对手（v1.11：野生精灵倒下 / 训练师轮战每只精灵倒下）
  └─ settleGrowth(Pokemon defeated)            // BattleEngine 私有
       ├─ survivors = 过滤 player.getParty() 中未倒下者
       ├─ growthPort.settle(survivors, List.of(defeated))   // defeated 恒为一只
       ├─ 逐行 append(settlement.log())          // 引擎只做日志搬运
       └─ pendingLearns.addAll(...)              // 队列管理仍在引擎（可能在战斗中非空）

整场战斗获胜（PLAYER_WIN）
  └─ reportBattleWon()
       └─ growthPort.onBattleWon(survivors())   // 整场一次，供按场次统计（v1.11）

捕捉成功（tryCapture / useItem 路径，v1.10）
  └─ growthPort.onCaptured(wild.getSpecies().getId())   // 引擎只申报物种 id
```

- 击倒申报与胜负**无关**：只要对手倒下就申报，因此**战败也不会回收已发放的经验**；
- 训练师轮战在 `switchToNextHealthy()`（派出下一只）**之前**申报，申报的必是刚倒下的那一只；
- `onBattleWon` 在 `status = PLAYER_WIN` 之后调用，整场战斗**只调用一次**；
- 野生遭遇申报「野生精灵」，训练师轮战**逐只**申报被击败对手（经验分配策略由成长模块决定）；
- 训练师轮战**不可捕捉**，因此 `onCaptured` 只会在野生遭遇路径触发；
- `onCaptured` 在野生精灵**已入队之后**调用，且引擎不追加任何日志行（捕捉文案由原有逻辑产生，
  避免重复输出）；
- `BattleService#pendingLearnChoices()` 返回成长模块挂起的抉择；`decideLearn(int)` 只做
  队列出入队 + 转发给 `resolveLearn`，文本行为全部由成长模块产生；
- 未注入成长端口时使用 `BattleGrowthPort.none()`：战斗规则照常运行，击倒与获胜后不做任何成长。

### 13.3 外部实现：`GrowthService`

全限定名：`org.example.growth.GrowthService`（`final`，实现 `BattleGrowthPort`），
组装层经 `org.example.integration.PokemonBattleAdapter#battleGrowthPort(BattleDataPort[, GrowthProgress])`
创建，与战斗模块**共用同一份** `BattleDataPort`。

| 规则 | 说明 |
|------|------|
| 经验折算（v1.11） | 被击败精灵**种族经验值 `Species#getBaseExpYield()` × 对方等级 / 7**，单只不低于 30；种族未提供 baseExp（= 0）时退化为「六维种族值总和 × 等级 / 5」 |
| 逐只即时发放（v1.11） | 战斗模块**每击倒一只**申报一次，成长模块立即结算该只经验：中途倒下的精灵也能拿到已击倒对手的经验，**战败不回收** |
| 到级学招 | `Species#moveLearnedAt(level)` 取技能 id → 经数据端口查 `Move`；有空槽直接学会，满 4 招挂起 |
| 进化 | `canEvolve()` 满足时经数据端口查目标种族（查不到则不进化），进化后重算属性并回满 |
| 降级 | 数据端口查不到技能 / 种族时，学招与进化静默跳过；经验与升级照常结算 |
| 图鉴进度（v1.11） | 持有 `GrowthProgress`：`onBattleWon` 按参战精灵累计该族**对战次数**（按**场次**计，逐只击倒不计数），`onCaptured` 累计该族**捕捉次数** |
| 本地永久存档（v1.10） | `GrowthProgress` 由 `GrowthProgressStore` 载入并绑定自动保存：每次捕捉/对战/清档后立即落盘，**关闭程序再打开仍保留**（详见 §13.7） |

> **职责对照**：升级 `Pokemon#addExp`、习得表 `Species#moveLearnedAt`、进化 `Pokemon#evolveTo`
> 等模型能力仍在 `org.example.model`；**判定规则**（何时算、算多少、学哪招）自 v1.9 起只存在
> 于成长模块，战斗模块不含任何经验曲线或习得表。

### 13.4 解耦收益

- 战斗模块可**单独测试**：不接成长模块时（默认空端口）战斗行为与原版一致，无成长副作用；
- 成长规则可替换：升级曲线、学招策略、进化条件改动只影响成长模块，战斗模块与 UI 不动；
- 结算**申报式**而非查询式：引擎不需要知道成长模块"想查什么"，只把事实（谁参战、谁被击败）
  交出去，成长模块可自由决定经验分配（如仅出战精灵得经验、道具加成等）。

### 13.6 个体值与属性演算（v1.10）

成长机制提升的是**个体值**，因此个体值必须真实参与战斗模型的面板演算，否则加成不可见。

| 项 | 规则 |
|----|------|
| 战斗模型公式 | `Pokemon#computeStats(species, level, ivs)`：HP = `(2×种族值 + 个体值) × 等级 / 100 + 等级 + 10`，其余五项为 `(2×种族值 + 个体值) × 等级 / 100 + 5` |
| 个体值来源 | `Pokemon#create(species, level, movePool[, ivs])`；省略 `ivs` 时按 `Stats.randomIv()` 随机 0~31 |
| 升级重算 | `applyStatsOnLevelUp()` 使用个体持有的 `ivs`，升级不会让个体值漂移 |
| 跨模块搬运 | `PokemonBattleAdapter#toBattlePokemon` 把新体系的个体值经 `toBattleStats` 显式搬运；**此前该字段在接缝处被丢弃并重新随机**（旧行为），v1.10 起保留 |
| 种族值不变 | 个体值加成只作用于个体值，`Species#getBaseStats()` 与性格一律不受影响 |

> 兼容性：个体值全 0 时新公式与旧公式（`种族值 × 2 × 等级 / 100`）等价，因此仅当个体值 > 0
> 时面板才比旧版更高；既有测试用精灵的速度 / 耐久断言不受影响。

### 13.7 成长进度的本地永久存档（v1.10）

个体值成长是**本地单机永久**机制：关闭程序、重开游戏、开启新一轮远征后，已获得的加成必须仍然生效。

| 项 | 规则 |
|----|------|
| 存档位置 | `<用户主目录>/.pokerouge/growth-progress.txt`（`GrowthProgressStore#defaultFile()`）；放用户主目录而非工程目录，重新构建 / 切分支 / 清 `target` 都不丢档 |
| 存档格式 | UTF-8 文本，含格式头与说明注释，每行 `物种id=捕捉次数,对战次数`，按物种 id 排序，人类可读、可手工清档 |
| 载入时机 | `GrowthProgress#instance()`（进程级单例）首次访问时经 `GrowthProgressStore#loadProgress()` 从文件载入并**绑定自动保存**；新增的 `GameSession` / `PokemonServiceImpl` / 战斗组装都会取到同一份已载入的进度 |
| 保存时机 | `recordCapture` / `recordBattle` / `clear` 之后立即落盘（原子写：先写 `.tmp` 再替换，避免中途崩溃损坏存档） |
| 上限 | `IvGrowthRule#MAX_IV = 31`。上限在**规则层**强制，因此即便手工把文件次数改到数千，游戏内加成仍封顶 31 |
| 重开存档 | `GrowthProgress#clear()` 同时清空内存与存档文件 |
| 容错 | 读取失败 / 内容损坏 → 按新档处理；单行格式错误只跳过该行，不整档报废；写入失败（目录只读 / 被占用）→ 只打日志，本局进度仅存内存，**不抛异常、不中断战斗** |
| 测试隔离 | `GrowthProgress` 默认构造（`new`）为纯内存、不触碰磁盘；`PokemonBattleAdapterTest` / `PokemonSystemValidator` 已改为注入独立实例，避免读到开发者本机真实存档 |

> 与「存档系统」的关系：本机制自带极简存档，**不依赖**尚未实现的存档系统
> （`StartView` 的「继续游戏」仍为预留入口）。后续若接入完整存档系统，只需改用
> `GrowthProgressStore#at(Path)` 指向统一存档目录，或经 `GrowthProgress#restore(...)` /
> `attachSaver(...)` 交由存档模块托管，成长规则与战斗模块无需改动。

## 15. 可携带装备（HeldItem）效果结算（v1.10）

### 15.1 装备模型与接入方式

装备定义在数据模块：`org.example.model.HeldItem`（id/name/effectType/param/description）与
枚举 `org.example.model.HeldItemEffect`（6 种效果）。数据源 `data/equipment.csv` 由数据模块
`GameData` 注册（8 件内建装备 + CSV 覆盖加载）。

| 效果类型 | param 约定 | 装备 |
|------|------|------|
| `DAMAGE_TYPE` | `属性|倍率`（如 `FIRE|1.2`） | 木炭/神秘水滴/磁铁 |
| `SUPER_EFFECTIVE` | 倍率（如 `1.2`） | 达人带 |
| `END_TURN_HEAL` | 最大 HP 比例（如 `0.0625`） | 剩饭 |
| `LIFE_STEAL` | 造成伤害比例（如 `0.125`） | 贝壳之铃 |
| `FIRST_STRIKE` | 触发百分比（如 `20`） | 先制之爪 |
| `EVOLITE` | 防御倍率（如 `1.5`） | 进化辉石 |

接入方式与道具一致：装备由**外部流程**（肉鸽 REWARD 事件发放 + UI 图鉴弹窗穿戴）设置到
`Pokemon#setHeldItem`，战斗模块**只读取**，不走 `BattleDataPort`；未穿戴（`heldItem == null`）
时全部效果静默不生效。

### 15.2 效果结算点

| 效果 | 结算位置 | 规则 |
|------|------|------|
| `FIRST_STRIKE` | 先后手判定 `firstMover` | 携带者按 `chanceParam()` 概率无视速度先手；**双方均触发时回退到速度判定**；日志「XX 的先制之爪抢先行动！」 |
| `DAMAGE_TYPE` | 伤害计算 `computeDamage` | 攻击方携带且招式属性与 `typeParam()` 一致时，最终伤害乘 `doubleParam()` |
| `SUPER_EFFECTIVE` | 伤害计算 `computeDamage` | 攻击方携带且克制（effectiveness > 1.0）时，最终伤害乘 `doubleParam()` |
| `EVOLITE` | 伤害计算 `computeDamage` | 防守方携带且仍有进化目标（`getEvolvesToId() != null`）时，物防/特防乘 `doubleParam()` |
| `LIFE_STEAL` | 攻击结算 `performAttack` | 攻击方携带且实际造成伤害 > 0 时，回复 `伤害 × doubleParam()`（截断） |
| `END_TURN_HEAL` | 回合末 `applyFieldEndEffects` | 双方携带者未倒下时回复 `maxHp × doubleParam()`（截断，至少 1） |

> 装备倍率参与公式：`floor(基础 × STAB × 克制 × 天气场地 × 装备 × 随机浮动)`，
> 与天气/场地加成同层级相乘。

## 16. 战斗演出事件：`BattleEvent`（v1.11）

### 16.1 定位

`BattleEvent` 是战斗引擎产出的**结构化演出数据**，与 `getLog()` 的**文本**日志互补：

| 通道 | 形态 | 用途 | 谁用 |
|------|------|------|------|
| `getLog()` | `List<String>` 文本行 | 给人读的战斗播报 | 日志面板、控制台演示 |
| `drainEvents()` | `List<BattleEvent>` 结构数据 | 驱动动画：谁、对谁、什么属性/分类的招式 | 战斗界面（`BattleView`） |

日志只说「发生了什么」，无法结构化解读；事件携带阵营、精灵名、招式名、属性、分类与成败标志，
界面据此选择动画形态与配色（如火系特殊招式 → 橙色发光球，变化招式 → 空心脉冲环）。

> **重点是「不参与结算」**：事件是纯演出旁路。忽略全部事件的调用方（例如控制台演示
> `org.example.demo.BattleConsole`）行为与本特性引入前**完全一致**；事件不改变伤害、命中、
> 捕捉、逃跑等任何判定结果。

### 16.2 契约

```java
public record BattleEvent(Kind kind, Side side, String actor, String moveName,
                          ElementType element, MoveCategory category, boolean success, Hp hp)
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `kind` | `Kind` | 事件类型（见 16.3） |
| `side` | `Side` | 事件主角阵营；`BATTLE_START` 为 `null`（表示双方） |
| `actor` | `String` | 主角名：精灵名；`CAPTURE` 为球名、`ITEM` 为道具名 |
| `moveName` | `String` | 招式名；非 `MOVE` 事件为空串 |
| `element` | `ElementType` | 招式属性（决定动画配色）；无数据时为 `null` |
| `category` | `MoveCategory` | 招式分类（决定动画形态）；无数据时为 `null` |
| `success` | `boolean` | 该事件是否成功（投球是否捕捉成功、逃跑是否成功）；其余事件恒为 `true` |
| `hp` | `Hp` | 受影响一方**变化后**的 HP 快照（v1.12 新增，见 16.6）；无 HP 变化时为 `Hp.NONE` |

嵌套枚举：

| 枚举 | 常量 |
|------|------|
| `BattleEvent.Kind` | `BATTLE_START` / `SEND_OUT` / `RECALL` / `MOVE` / `HIT` / `FAINT` / `CAPTURE` / `ITEM` / `RUN` |
| `BattleEvent.Side` | `PLAYER`（玩家一方）/ `FOE`（对手一方） |

实例方法：`Side opponent()` —— 返回与本事件阵营相对的另一方（`BATTLE_START` 返回 `null`）。

常量：`BattleEvent.STRUGGLE_NAME`（`"挣扎"`）—— PP 耗尽后无招式攻击时 `MOVE` 事件携带的招式名。

### 16.3 事件类型与产生时机

| `Kind` | 对应动画 | 产生时机 | `side` |
|--------|----------|----------|--------|
| `BATTLE_START` | 进场动画 | 引擎构造完成时（每个战斗实例恰好一次） | `null` |
| `SEND_OUT` | 放出动画 | 玩家主动换宠、**玩家倒下后补位**（`chooseReplacement`）、训练师派出下一只 | 派出方 |
| `RECALL` | 收回动画 | 玩家主动换宠（先收回再放出） | `PLAYER` |
| `MOVE` | 技能释放（施法） | 任一方成功使出招式（含变化招式与挣扎） | 施法方 |
| `HIT` | 受击（命中） | **实际造成伤害**时；变化招式命中目标时 | 被打方 |
| `FAINT` | 倒下 | 精灵 HP 归零（攻击、混乱自伤、回合末持续伤害、天气侵蚀） | 倒下方 |
| `CAPTURE` | 投球 | 玩家投出精灵球（野生遭遇） | `FOE` |
| `ITEM` | 回复特效 | 玩家使用回复 / 解除类道具且实际生效 | `PLAYER` |
| `RUN` | 逃跑 | 玩家尝试逃跑（仅野生遭遇） | `PLAYER` |

**不发事件的情形**（有意为之，避免"无效果也演一遍"的错位感）：

- 招式落空、被属性免疫、打出「没有效果……」时**不产生** `HIT`；
- PP 不足、目标非法、道具未实际生效等「本回合不行动」的情况不产生任何事件；
- 训练师轮战的逃跑 / 投球被拒绝时只追加日志，不产生事件。

**顺序保证**：事件严格按产生顺序排列，且与同回合日志行顺序一致；每个事件携带的 `hp` 快照
即该步发生时的真实血量。例如「我方一招击倒敌方，训练师派出下一只」的事件序列为：

```
MOVE(PLAYER, ...) → HIT(FOE, hp=0) → FAINT(FOE, hp=0) → SEND_OUT(FOE, hp=满血)
```

双方各出手一次的回合则是 `MOVE / HIT` 交替出现（先手方的 `MOVE` → 对方的 `HIT` → 对方的
`MOVE` → 先手方的 `HIT`），界面因此在**每段动画开始前**就能取到该段应有的血量。

### 16.4 取走语义

`drainEvents()` 是**取走并清空**：返回自上次调用以来新产生的事件，队列随即清空，同一事件不会
重复投递；无新事件时返回空列表。

```java
engine.useMove(slot);                       // 1. 结算（事件入队，含 HP 快照）
List<BattleEvent> events = engine.drainEvents(); // 2. 取走事件
view.playEvents(events, () -> view.render());    // 3. 播动画（逐步按快照刷血条）→ 结束后再刷新界面
```

> **推荐顺序**：行动 → 取事件 → 播动画 → 动画结束后再刷新界面。HP 条由 `playEvents` 在**每一步
> 动画开始前**按该事件的 `hp` 快照刷新（见 16.6），因此不会出现「双方都演完才一起结算血量」；
> 立绘、精灵名、等级、异常状态徽章等仍应在**整段动画结束后**统一刷新 —— 引擎可能已在结算时
> 自动换宠 / 补位，先把这些字段刷成最终状态会让倒下与放出动画作用到错误的精灵上。

### 16.6 HP 快照与「先扣血、再播动画」

`BattleEvent.Hp`（v1.12 新增）把该事件造成的 HP 变化**随事件一起投递**，避免界面靠「自己在动画
结束后重新读精灵对象」才能知道血量：

```java
public record Hp(int current, int max) {
    public static final Hp NONE = new Hp(-1, -1);   // 无 HP 变化
    public boolean present() { return current >= 0 && max > 0; }
}

public static Hp hpOf(Pokemon p);   // p == null → Hp.NONE；否则取 p 的实时 current/max
```

| 事件类型 | `hp` 快照归属 |
|----------|----------------|
| `HIT` | **受击方**扣血后的数值（`performAttack` / 挣扎 / 自身混乱自伤 / 变化招式） |
| `FAINT` | 倒下方的数值（`0`） |
| `SEND_OUT` | **新上场精灵**的当前 HP（含倒下后的玩家补位 / 敌方自动派出） |
| `ITEM` | **场上**精灵回复后的数值（道具可能回复后备精灵，此时场上血量不变，刷新同样正确） |
| `MOVE` / `RECALL` / `CAPTURE` / `RUN` / `BATTLE_START` | `Hp.NONE` |

要点：

* **先扣血、再播动画**。界面在播放每一步动画**之前**就按 `hp` 刷新该侧血条，因此玩家看到的是
  「技能打中 → 血条同时下降 → 播受击/倒下动画」，而不是「动画放完才掉血」。
* **逐方交替**。引擎本就按出手顺序交替产事件（先手 `MOVE` → 后手 `HIT` → 后手 `MOVE` → 先手
  `HIT`），配合逐步刷新即可实现「一方出手播完动画、血扣了，另一方再出手」，**无需**改动引擎
  的结算顺序或事件数量。
* **写入前先认名**。界面刷新血条时会比对事件 `actor` 与当前该侧显示的精灵名，只有一致才写入；
  这样倒下后补位的事件不会把上一只的血量刷到新上场的精灵头上。
* **兼容旧调用**。所有既有工厂方法（`sendOut` / `hit` / `faint` / `item` 等）签名保持不变，内部
  以 `Hp.NONE` 填充，因此不关心 HP 的调用方与既有测试无需改动。

## 17. 能力等级与命中率判定（v1.12）

### 17.1 能力等级

变化类技能（`MoveCategory.STATUS`）可增减双方的能力等级，遵循原版宝可梦规则：

| 能力项 | `Stat` 枚举 | 中文名 |
| --- | --- | --- |
| 物理攻击 | `ATTACK` | 物攻 |
| 物理防御 | `DEFENSE` | 物防 |
| 特殊攻击 | `SP_ATTACK` | 特攻 |
| 特殊防御 | `SP_DEFENSE` | 特防 |
| 速度 | `SPEED` | 速度 |

* **等级范围**：`-6 ~ +6`，超出即裁剪（`Pokemon.changeStatStage` 返回**实际**变化量，
  已达上下限时返回 `0`）。
* **倍率**（`Pokemon.stageMultiplier(int)`）：正等级为 `(2 + n) / 2`、负等级为 `2 / (2 - n)`，
  即 `0 → ×1`、`+2 → ×2`、`+6 → ×4`、`-2 → ×0.5`、`-6 → ×0.25`。
* **生效范围**：只影响对应能力项。`Pokemon.effectiveAttack()` / `effectiveDefense()` /
  `effectiveSpAttack()` / `effectiveSpDefense()` / `effectiveSpeed()` 为唯一读取入口，
  它们在面板值上依次乘算**能力等级倍率**与**异常状态倍率**（灼伤减物攻、麻痹减速度），下限 1。
  伤害公式（`BattleEngine.computeDamage`）与先后手判定已全部改走这些入口。
* **挥发性**：能力等级随**离场**消失——换宠、倒下补位、战斗开始（引擎构造）都会清零，
  **不写入存档**，`Pokemon.restore` 还原的个体一律从中立等级开始。
  `fullRestore()` / `fullHeal()` 亦一并清除。
* **播报**：按实际变化量输出「（大幅）提高了！/（大幅）下降了！/已经无法再提高了！/已经无法再下降了！」，
  幅度 ≥2 时加「大幅」。变化技能不再落到「但是什么也没有发生……」兜底。

### 17.2 `StatChange` 声明

```java
public record StatChange(Recipient recipient, Stat stat, int delta) {
    public enum Recipient { SELF, OPPONENT }
}
```

* `recipient` 为 `SELF`（使用者自己，如硬邦邦/高速移动）或 `OPPONENT`（招式目标，如叫声/摇尾巴）。
* `delta` 保留符号，构造时裁剪到 `[-6, 6]` 且不得为 `0`。
* 文本解析：`StatChange.parse("SELF:DEFENSE:+1")`；
  `StatChange.parseAll("SELF:SPEED:+2;OPPONENT:ATTACK:-1")` 返回列表（空值 / 非法项被忽略）。
* `Move` 新增第 12 个构造参数 `List<StatChange> statChanges` 与读取方法
  `getStatChanges()` / `hasStatChanges()`；既有 11 参数构造保持兼容（默认空列表）。

### 17.3 数据契约：`moves.csv` 的 `statChanges` 列

列序调整为 `id,name,type,category,power,accuracy,maxPp,priority,inflicts,inflictionChance,statChanges,effect`，
即 `statChanges` 占用 `c[10]`，`effect` 后移至 `c[11]`（历史数据中 `effect` 从未被填写，前移不影响兼容）。

当前已装配的能力等级招式：

| 招式 | 声明 | 含义 |
| --- | --- | --- |
| 叫声 `growl` | `OPPONENT:ATTACK:-1` | 对方物攻 -1 |
| 摇尾巴 `tail-whip` | `OPPONENT:DEFENSE:-1` | 对方物防 -1 |
| 硬邦邦 `harden` | `SELF:DEFENSE:+1` | 自身物防 +1 |
| 高速移动 `agility` | `SELF:SPEED:+2` | 自身速度 +2 |

### 17.4 命中率判定

变化类与伤害类招式在 `BattleEngine.executeMove` 入口统一做一次命中判定：

* `accuracy < 0`（必中，如硬邦邦/高速移动/暗影拳）与 `accuracy >= 100` **恒命中**，
  且**不消耗任何随机数**——保证无命中判定的历史随机序列完全不变。
* 仅 `0 ~ 99` 的命中率掷一次 `random.nextInt(100)`，`< accuracy` 即命中
  （如打雷 70、催眠粉 75、鬼火 85 现在**真的会落空**）。
* **未命中**：追加日志「<使用者> 的【<招式>】没有命中！」后直接返回——
  不造成伤害、不施加异常状态、不改变能力等级、**不产生任何演出事件**
  （出招动画已在行动开始时播报，命中事件缺失即代表落空）。
* PP 已在行动前扣除，未命中同样消耗 PP。

### 17.5 测试覆盖

`src/test/java/org/example/battle/BattleEngineStatStageTest.java`（20 个用例，个体值固定为 0）：

* **模型层**：倍率数值（0/±1/±2/±4/±6）、`changeStatStage` 的裁剪与实际变化量返回、
  只影响对应能力项、`clearStatStages()` 复原、`fullRestore()` 清除。
* **数据层**：`StatChange.parseAll` 的合法/非法/裁剪用例，以及 `GameData.move(id)` 上
  叫声／摇尾巴／硬邦邦／高速移动 的 `statChanges` 装配结果。
* **引擎层**：叫声降低对方物攻并削弱其输出（且不再出现无效果兜底文案）、硬邦邦提高自身物防、
  已达上限时的「已经无法再提高了」、高速移动改变先后手、战斗开始清空双方水平、
  换宠时下场精灵放弃等级。
* **命中率**：必中与命中率 100 **均不掷命中骰**（用记录 `nextInt(bound)` 的随机源断言）、
  未通过判定时不造成伤害 / 不播报伤害 / 不施加异常 / 不改变能力等级 / 不产生 HIT 事件、
  通过判定时正常造成伤害。

## 18. 专属变化技能与先制度（v1.13）

v1.13 把 `moves.csv` 中最后三个「有数据、无行为」的变化技能接通，并修掉一个此前一直存在
但未暴露的引擎缺陷：**先制度从未参与先后手判定**。

### 18.1 挥发性状态：`Pokemon`

守住与寄生种子需要在「当回合内」与「持续若干回合」两个时间尺度上记住状态，因此在
`Pokemon` 上新增挥发性（volatile）字段——它们与能力等级同类：**只在本次战斗中有效，不写入存档**。

| 字段 | 访问器 | 含义 |
| --- | --- | --- |
| `protectedThisTurn` | `isProtected()` / `setProtected(boolean)` | 本回合是否处于守住状态 |
| `protectStreak` | `getProtectStreak()` / `setProtectStreak(int)` | 连续使用守住的次数（决定成功率，`set` 会裁剪为 ≥0） |
| `seeded` | `isSeeded()` / `setSeeded(boolean)` | 是否被种下寄生种子 |

`Pokemon.clearVolatileState()`（v1.13 新增）一次性清除上表三项**与全部能力等级**。
引擎在以下时机调用它：

| 时机 | 位置 |
| --- | --- |
| 战斗开始（双方首发） | `BattleEngine` 构造 |
| 换宠（**下场方与上场方都清**） | `BattleEngine.switchActive` |
| 倒下补位（`chooseReplacement`） | `BattleEngine.chooseReplacement` |
| 回合结束的补位流程 | `resolveRoundEnd` |
| 道具「完全恢复」`fullRestore()` / `fullHeal()` | `Pokemon` |

因此**换宠可以洗掉寄生种子、也能放弃守住累计次数**，但守住状态本身只覆盖当回合
（见 §18.3），不会因为换宠被「提前取消」。

### 18.2 先制度判定

* `Move.getPriority()`（`moves.csv` 第 8 列）数值越大越先出手；相同才回退速度判定。
* `BattleEngine.firstMover(...)` 先比较双方招式的 `priority`，相同才调用
  `speedOrder(...)`（先制之爪 → `effectiveSpeed()` → 同速掷硬币）。
* **随机序列保持兼容**：双方先制度**都是 0** 时走快路径直接返回，不触碰先制之爪与同速硬币，
  与 v1.12 之前逐字节一致；只有真正出现非 0 先制度时才多消耗随机数。
* 敌方招式是**出手前随机抽取**的，为了让「敌方先制招式先手」成立，
  `BattleEngine` 在抽取前判断是否需要先定招式（`needsFoeMoveForOrder`）：
  仅当**敌方可用招式的先制度跨越多个取值**、且玩家招式先制度落在该区间内时，
  才预抽一次（`foePriorityRange` + `foeTurn(MoveSlot)`）；否则行为与旧版一致。
* 已装配非 0 先制度的招式：电光一闪 `quick-attack`（+1）、守住 `protect`（+4）。

### 18.3 守住 `MoveEffect.PROTECT`

| 招式 | id | 属性 | 类别 | 命中 | 先制度 | effect |
| --- | --- | --- | --- | --- | --- | --- |
| 守住 | `protect` | 一般 | 变化 | 必中（`-1`） | **+4** | `PROTECT` |

* **挡下范围**：当回合对该使用者的一切招式——**含伤害招与变化招**。
  `BattleEngine.blocksWithProtect(defender)` 在 `moveHits` **之前**拦截，
  被挡下时追加「<名> 用守住挡下了攻击！」，随后 `return`——**不掷命中骰、不产生 HIT 事件**，
  与「未命中」保持同一约定（界面靠「只有出手事件、没有受击事件」判断被挡下）。
* **成功率**：`chance = Math.max(1, 100 >> Math.min(streak, 30))`（`streak` 为**此前**连续使用次数），
  即 100% → 50% → 25% → 12.5% → 6% → 3% → 1% 并稳定在 1%；
  失败时播报「守住没有成功！」（仍记入连续次数）。
* **连续次数清零**：使用**非**守住招式时（`executeMove` 中判定）立刻置 0。
* **状态只覆盖当回合**：`finishRound` **开头**统一把双方 `protectedThisTurn` 置 `false`，
  保证第 N 回合的守住不会漏到第 N+1 回合。

### 18.4 寄生种子 `MoveEffect.LEECH_SEED`

| 招式 | id | 属性 | 类别 | 命中 | 先制度 | effect |
| --- | --- | --- | --- | --- | --- | --- |
| 寄生种子 | `leech-seed` | 草 | 变化 | 90 | 0 | `LEECH_SEED` |

* **作用对象是「目标」**：`applyLeechSeed(defender)` 只给**被命中一方**打上 `seeded`。
* **免疫与重复**：草系目标播报「因属性免疫」并直接返回；已带种子播报「已经被种下了寄生种子」。
* **回合末结算**：`applyFieldEndEffects` 在**剩饭回复之后、异常状态结算之前**依次执行
  `leechSeedDrain(pa, foe)` 与 `leechSeedDrain(foe, pa)`；
  被种下的一方失去 `max(1, maxHp / 8)`（受当前 HP 上限约束），
  **等量回复对方出战精灵**（`Pokemon.heal(实际吸取量)`，回复量以对方 HP 上限封顶）。
  播报「寄生种子吸取了 <名> 的养分，失去了 N HP！」与「<名> 恢复了 N HP！」；
  若因吸取倒下，立刻补「<名> 倒下了！」并终止本次结算。
* **注意**：吸取只在双方均未倒下时进行（沿用 `applyFieldEndEffects` 既有的 `bothStanding` 约束）。
* **离场清除**：见 §18.1。

### 18.5 睡觉 `MoveEffect.REST`

| 招式 | id | 属性 | 类别 | 命中 | 先制度 | effect |
| --- | --- | --- | --- | --- | --- | --- |
| 睡觉 | `rest` | 超能力 | 变化 | 必中（`-1`） | 0 | `REST` |

* **成功条件**：HP **未满**且**没有**主要异常状态。
  满血播报「<名> 睡觉失败！」，已有异常播报「<名> 无法睡觉！」——此时**不回复 HP、不改变异常**。
* **成功效果**：HP 回满，并施加 `StatusCondition.SLEEP`，睡眠计数为
  **`StatusCondition.REST_SLEEP_TURNS = 2`**（v1.13 新增常量）。
* 与既有 `tickSleep()` 的配合：睡眠计数在**行动前**先递减再判断，因此计数 2 表示
  「施放当回合 + 下一回合」无法行动，再下一回合醒来（与 `BattleEngineStatusTest`
  既有用例语义一致）。播报「<名> 睡着了！」→「<名> 正在呼呼大睡……」→「<名> 醒过来了！」。
* 睡眠仍可被「解眠药 / 全体回复」等既有解除道具清除（§10.6）。

### 18.6 `MoveEffect` 常量与数据契约

`MoveEffect` 新增三个常量，并新增 `isFieldEffect()`：

```java
public enum MoveEffect {
    NONE, SUNNY_DAY, RAIN_DANCE, SANDSTORM, ELECTRIC_TERRAIN, GRASSY_TERRAIN, PSYCHIC_TERRAIN,
    PROTECT, LEECH_SEED, REST;   // v1.13 新增

    /** 是否为天气/场地类「场况」效果（与专属效果区分）。 */
    public boolean isFieldEffect() { return toWeather() != null || toTerrain() != null; }
}
```

`moves.csv` 的 `effect` 列（`c[11]`，见 §17.3）现取值约定：

| 取值 | 含义 |
| --- | --- |
| 留空 | 无专属效果（沿用「能力等级 / 异常状态 / 兜底文案」流程） |
| `SUNNY_DAY` 等 | 开启对应天气 |
| `ELECTRIC_TERRAIN` 等 | 开启对应场地 |
| `PROTECT` | 守住（§18.3） |
| `LEECH_SEED` | 寄生种子（§18.4） |
| `REST` | 睡觉（§18.5） |

`BattleEngine.applyFieldEffect(attacker, defender, effect)` 是该列的唯一消费入口：
先处理 `null` / `NONE` 兜底，再处理天气与场地，最后 `switch` 分发到
`applyProtect(attacker)` / `applyLeechSeed(defender)` / `applyRest(attacker)`。
每个分支都有**确定的播报**，不会落入「但是什么也没有发生……」。
`Move` 的类 javadoc 同步说明「变化类技能可附带天气/场地或专属效果」，
`priority` 字段的 javadoc 由「暂未启用」改为「相同才回退速度判定」。

### 18.7 界面展示（`BattleView`）

* **状态徽章**（`statusBadgeText`）扩展为可按序拼接多项：
  `已倒下` > `守住` > `寄生种子` > 主要异常 > `混乱`（空格分隔，无内容整行隐藏）。
  守住与寄生种子会在`BattleController.render()` 每次刷新时自动跟随。
* **技能效果行**（`moveEffectText`）为三个新效果补上说明文案：
  「效果：本回合挡下对方的一切招式」/「效果：每回合吸取目标最大 HP 的 1/8」/
  「效果：回满 HP 并睡眠 2 回合」。

### 18.8 测试覆盖

`src/test/java/org/example/battle/BattleEngineSpecialStatusMoveTest.java`（**20** 个用例，

## 19. 倒下后的玩家补位（v1.14）

### 19.1 动机

v1.13 及之前，己方出战精灵倒下时由引擎在 `resolveRoundEnd` 中直接调用
`Player.switchToNextHealthy()` 自动补位，玩家没有选择权，界面也无法表达「该派谁上场」。
v1.14 把这一步改为**挂起 + 玩家选择**。

### 19.2 设计：引擎侧硬门禁 + 界面侧选择面板

| 层 | 职责 |
|----|------|
| `BattleEngine`（唯一实现） | 倒下时置 `awaitingReplacement = true` 并追加提示；`requirePlayerAction()` 检查该标志，**整场行动方法的唯一入口**都经它把关，等待期间一律抛 `IllegalStateException`；新增 `isAwaitingReplacement()` / `chooseReplacement(int)` |
| `BattleView` | 新增 `Actions.onReplacementSelected(int)` 与 `showReplacementMenu(party, activeIndex, onPick)`；`renderPartyGrid` 的 `onBack` 允许为 `null`（补位面板**不可返回**） |
| `BattleController` | `render()` 在 `isOngoing()` 之后**优先**判断 `isAwaitingReplacement()`，是则弹出补位面板并 `return`，不进入主菜单 |
| `BattleConsole`（demo） | 主循环插入 `doReplacement(b)`，与界面行为对齐 |
| `BattleService`（契约） | 声明两个新方法；行动方法的 javadoc 补充 `@throws` 说明 |

**为什么用硬门禁**：等待补位时 `status` 仍为 `ONGOING`，如果只在界面层拦截，
控制台 demo、测试或未来任何新调用方都能绕过选择直接 `useMove`，
从而出现「倒下的精灵继续攻击」这类不一致状态。把约束放在引擎里，任何调用方都必须先补位。

### 19.3 行为细节

* **不消耗回合**：`chooseReplacement` 不是回合行动，敌方不会行动（区别于 `switchActive`）；
* **中立状态开始**：上场精灵执行 `clearVolatileState()`（能力等级、守住、连续次数、寄生种子，
  混乱由 `takeDamage` 在倒下时另行清除）；
* **演出事件**：压入一条 `SEND_OUT`（`Side.PLAYER`），携带新上场精灵的 HP 快照，
  与旧自动换宠完全一致，因此动画层无需改动；
* **非法选择**：目标为已倒下精灵 / 下标越界时追加「倒下的精灵不能上场，请选择其他精灵。」
  且**保持等待**（`activeIndex` 不变，可重试）；
* **判负**：判负条件由 `switchToNextHealthy() == null` 改为 `player.hasHealthyPokemon()`，
  语义等价但**不再改动 `activeIndex`**；
* **同回合双倒**：`resolveRoundEnd` 仍先处理敌方倒下再处理己方，边界行为与旧实现一致；
* **训练师方不变**：`Trainer` 侧仍由引擎自动派出下一只健康精灵。

### 19.4 测试覆盖

新建 `src/test/java/org/example/battle/BattleEngineReplacementTest.java`（**8** 个用例）：

* **硬门禁**：等待补位时战斗未结束但 `useMove` / `tryRun` / `switchActive` / `useItem`
  全部抛 `IllegalStateException`，且等待状态不变；非等待状态下调用 `chooseReplacement` 抛异常。
* **补位语义**：补位后恢复行动、新精灵满血上场；补位产生玩家方 `SEND_OUT` 事件；
  补位上场的精灵从中立状态开始（能力等级与寄生种子被清除）。
* **非法选择**：选择已倒下精灵不生效且保持等待（日志含「倒下的精灵不能上场」）；
  越界下标不生效且保持等待。
