# 战斗服务（BattleService）接口文档

> 版本：v1.1 · 日期：2026-09-08 · 模块：`org.example.battle`（PokeRouge）
>
> v1.1：新增天气与场地系统（状态查询 `getWeather()/getTerrain()`、变化类技能开启、
> 持续回合推进与回合末效果），详见 §7。

## 1. 概述

本模块把「回合制战斗逻辑」从界面/控制器中独立出来，对外暴露一个稳定接口
`BattleService`，供主界面、战斗界面等调用方使用。调用方只依赖接口，具体结算规则由
实现类 `BattleEngine` 承担，实例统一由静态工厂 `BattleServices` 创建。

设计目标：

- 战斗规则（伤害、速度先后手、捕捉、逃跑、经验/升级/学招/进化、天气与场地）与 UI 完全解耦；
- 调用方不直接依赖具体实现类，便于测试注入随机源、后续替换实现；
- 以「每回合新增日志行」作为行动结果的统一反馈通道。

## 2. 模块结构

```
org.example.battle
├── BattleService.java   [接口] 战斗服务契约（本文档主体）
├── BattleServices.java  [工厂] 创建战斗实例 + 遭遇环境助手（静态）
└── BattleEngine.java    [实现] 回合制对战引擎（默认/唯一实现）
```

依赖的模型类型（均位于 `org.example.model`）：`Player`、`Pokemon`、`MoveSlot`、
`Item`、`Bag`，以及天气/场地系统相关枚举 `Weather`、`Terrain`、`MoveEffect`（见 §7）。

## 3. 接口：`BattleService`

全限定名：`org.example.battle.BattleService`

### 3.1 嵌套枚举 `Status`（战斗状态）

| 常量         | 含义                     | 触发场景                         |
|--------------|--------------------------|----------------------------------|
| `ONGOING`    | 进行中                   | 战斗尚未结束，可继续行动         |
| `PLAYER_WIN` | 玩家获胜                 | 野生精灵倒下，结算经验/升级/进化 |
| `PLAYER_LOSE`| 玩家战败                 | 队伍全部倒下且无精灵可替换       |
| `FLED`       | 逃跑成功                 | `tryRun()` 成功                 |
| `CAUGHT`     | 捕捉成功                 | 精灵球捕捉成功并加入玩家队伍     |

### 3.2 回合行动方法

所有行动方法均**要求战斗进行中**（`status == ONGOING`），否则抛出
`IllegalStateException`。返回值为**本回合新产生**的日志行（非全量日志）。

#### `List<String> useMove(MoveSlot slot)`

玩家选择技能攻击。野生精灵自动选择可用技能；双方都行动时按速度决定先后手，
速度相同则随机。

| 项     | 说明 |
|--------|------|
| 参数   | `slot`：当前出战精灵的技能槽；`null` / PP 耗尽 / 非当前精灵的槽位会自动退回当前精灵第一个可用技能；完全无可用技能则本回合不行动 |
| 返回   | 本回合新增日志行 |
| 副作用 | 消耗 PP；**变化类技能**若携带天气/场地效果（`MoveEffect`）则改为开启/重置对应天气/场地（见 §7），不造成伤害；普通技能命中则计算伤害；若击倒野生精灵进入 `PLAYER_WIN`，玩家精灵倒下自动换宠或进入 `PLAYER_LOSE` |

#### `List<String> useItem(Item item)`

使用道具。按道具类别分流：`HEAL` 回复当前精灵 HP；`POKE_BALL` 尝试捕捉野生精灵
（捕捉公式：血量越低、捕获率越高、球倍率越大越易成功，必定捕捉球直接成功）。

| 项     | 说明 |
|--------|------|
| 参数   | `item`：要使用的道具；`null` 或背包中数量不足则不行动 |
| 返回   | 本回合新增日志行 |
| 副作用 | 回复道具会消耗背包对应数量；精灵球使用后无论成败都会消耗；使用后若战斗未结束，野生精灵行动一次 |

#### `List<String> tryRun()`

尝试逃跑。成功率 = `0.35 + 0.6 × (我方速度 / (我方速度 + 敌方速度))`，
速度越接近成功率越低（约 0.65），远超时接近 0.95。

| 项     | 说明 |
|--------|------|
| 返回   | 本回合新增日志行 |
| 副作用 | 成功 → `FLED`；失败 → 野生精灵行动一次 |

#### `List<String> switchActive(int partyIndex)`

消耗本回合行动切换出战精灵，收换完成后野生精灵行动一次。

| 项     | 说明 |
|--------|------|
| 参数   | `partyIndex`：玩家队伍中目标精灵下标 |
| 返回   | 本回合新增日志行 |
| 副作用 | 目标与当前相同 / 下标非法 / 目标不存在时不行动（不消耗回合） |

### 3.3 状态查询方法

| 方法签名 | 返回 | 说明 |
|----------|------|------|
| `Player getPlayer()` | 玩家 | 本场战斗的玩家（含队伍与背包） |
| `Pokemon getWild()` | 野生精灵 | 本场战斗的野生精灵 |
| `Pokemon playerActive()` | 出战精灵 | 玩家当前出战精灵；倒下被引擎自动切换后可能为 `null` |
| `Status getStatus()` | 战斗状态 | 见 3.1 |
| `boolean isOngoing()` | 是否进行中 | 等价 `getStatus() == Status.ONGOING` |
| `List<String> getLog()` | 日志 | 完整战斗日志（只读，不可修改） |
| `Bag getBag()` | 背包 | 便捷转发，等价 `getPlayer().getBag()` |
| `Weather getWeather()` | 天气 | 当前天气；无天气为 `Weather.NONE`，由天气类变化技能开启（见 §7） |
| `Terrain getTerrain()` | 场地 | 当前场地；无场地为 `Terrain.NONE`，由场地类变化技能开启（见 §7） |

## 4. 工厂：`BattleServices`

全限定名：`org.example.battle.BattleServices`（`final`，私有构造，禁止实例化）

| 方法签名 | 返回 | 说明 |
|----------|------|------|
| `BattleService newBattle(Player player, Pokemon wild)` | 战斗实例 | 创建默认随机源的新对战；玩家无存活出战精灵或野生无效时抛 `IllegalArgumentException`，参数为 `null` 抛 `NullPointerException` |
| `BattleService newBattle(Player player, Pokemon wild, Random random)` | 战斗实例 | 同上有随机源版本（便于测试复现） |
| `int wildLevelAround(int playerLevel)` | 建议等级 | 野生等级在 `[playerLevel-2, playerLevel+2]` 内随机，最低 2 |
| `Optional<Pokemon> randomWild(int aroundLevel)` | 野生精灵 | 从数据注册表（`GameData#wildPool()`）随机挑选；无野生池数据返回 `Optional.empty()` |

## 5. 使用示例

```java
// 1) 组装玩家（队伍 + 背包），进入随机遭遇
Player player = ...;                       // 需有存活出战精灵
int level = BattleServices.wildLevelAround(player.getActive().getLevel());
Optional<Pokemon> wild = BattleServices.randomWild(level);
if (wild.isEmpty()) return;

// 2) 创建战斗服务（返回的是接口类型）
BattleService battle = BattleServices.newBattle(player, wild.get());

// 3) 回合驱动：进行中则让玩家选择一个行动
while (battle.isOngoing()) {
    List<String> lines = battle.useMove(currentMoveSlot); // 技能 / useItem / tryRun / switchActive
    for (String line : lines) logView.append(line);
}

// 4) 依据结果状态收尾
switch (battle.getStatus()) {
    case PLAYER_WIN -> onWin(battle.getPlayer());
    case PLAYER_LOSE -> onLose();
    case FLED       -> backToMap();
    case CAUGHT     -> onCaught(battle.getWild());
    case ONGOING    -> { /* 不应出现 */ }
}
```

## 6. 回合驱动流程（状态机）

```
        ┌─────────────────────────────────────────────────────┐
        │  ONGOING  (玩家每回合选择 技能/道具/逃跑/换宠)       │
        │  ┌───────────────────────────────────────────────┐  │
        │  │ 引擎内部结算：                                 │  │
        │  │   先后手 → 伤害 → 胜负 → 经验/升级/进化        │  │
        │  │   回合末：结算天气/场地效果并推进剩余回合       │  │
        │  └───────────────────────────────────────────────┘  │
        └──────────┬──────────────┬───────────────┬──────────┘
                   ▼              ▼               ▼
              PLAYER_WIN     PLAYER_LOSE     FLED / CAUGHT
```

- 行动期间精灵倒下会被引擎自动切换下一只健康精灵；
- 胜利后向队伍中未倒下精灵发放全额经验，逐级结算升到级学招与进化；
- 每回合行动结束后（双方仍站场时）引擎结算天气/场地回合末效果，并推进
  天气/场地剩余回合（见 §7）。

## 7. 天气与场地

战斗双方共享同一片天气（`Weather`）与场地（`Terrain`），由携带对应效果的
**变化类技能**开启，持续固定回合后自然消退，持续期间影响招式威力和回合末效果。

### 7.1 开启与持续

- **开启方式**：使用带效果的变化类技能（如「大晴天」「青草场地」）。普通物理/特殊
  技能不影响天气与场地。效果枚举 `MoveEffect`（`org.example.model`）把技能映射到
  对应 `Weather` / `Terrain`。
- **持续回合**：`Weather.DURATION_TURNS` / `Terrain.DURATION_TURNS` 均为 5 回合
  （含开启当回合）。每回合末引擎推进计数，归零后天气/场地消退并写入结束消息
  （如「沙暴平息了。」「青草场地的效果消失了。」）。
- **覆盖与重置**：再次开启同类天气/场地会重置剩余回合并提示「持续回合重置了！」；
  开启不同类的天气/场地则替换前一类。天气与场地相互独立，可同时生效。

### 7.2 效果明细

| 状态 | 开启技能效果（`MoveEffect`） | 招式威力倍率 | 回合末效果 |
|------|------------------------------|--------------|------------|
| `Weather.SUNNY` 大晴天 | `SUNNY_DAY` | 火系 ×1.5 | — |
| `Weather.RAIN` 下雨 | `RAIN_DANCE` | 水系 ×1.5 | — |
| `Weather.SANDSTORM` 沙暴 | `SANDSTORM` | — | 非岩石/地面系扣最大 HP 的 1/16 |
| `Weather.HAIL` 冰雹 | `HAIL` | — | 非冰系扣最大 HP 的 1/16 |
| `Terrain.ELECTRIC` 电气场地 | `ELECTRIC_TERRAIN` | 电系 ×1.3 | — |
| `Terrain.GRASSY` 青草场地 | `GRASSY_TERRAIN` | 草系 ×1.3 | 场上非飞行系精灵回复最大 HP 的 1/16 |
| `Terrain.MISTY` 薄雾场地 | `MISTY_TERRAIN` | 龙系 ×0.5 | — |
| `Terrain.PSYCHIC` 精神场地 | `PSYCHIC_TERRAIN` | 超能力系 ×1.3 | — |

规则细节：

- 天气与场地的倍率**可叠加**（伤害计算时按 天气倍率 × 场地倍率 连乘）；
- 回合末效果（沙暴/冰雹扣血、青草回复）仅在**双方都仍站场**时结算；满血精灵不会
  产生回血日志；免疫精灵不产生扣血日志；
- 变化类技能同样消耗 PP 与整回合行动，规则与伤害技能一致（只是不造成伤害）；
- 战斗结束（胜负/逃跑/捕获）后天气/场地不残留到下一场。

### 7.3 界面展示

UI 层通过 `getWeather()` / `getTerrain()` 在每次行动后刷新状态条，展示
`Weather.getDisplayName()` / `Terrain.getDisplayName()`（如「大晴天」「青草场地」）。

## 8. 实现与扩展约束

- 唯一实现 `BattleEngine`（同包），构造时校验玩家出战精灵与野生精灵均有效；
- 调用方应通过 `BattleServices` 获取实例，禁止 `new BattleEngine(...)`；
- 若需新增自定义实现，实现 `BattleService` 即可，UI 层无需改动。
