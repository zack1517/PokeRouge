## 二、既有类补齐（兼容签名，不改语义）

- **ElementType**：构造带色码，新增 `getColorCode()`（§2.1，CSS 色）
- **Move**：`isPhysical()` / `isSpecial()`（已有 `isStatus`）
- **MoveSlot**：`getCurrentPp` / `getMaxPp` / `isExhausted` / `usePp` / `restorePp` / `fullRestore`（保留原 use/restore/exhausted 别名）
- **Stats**：`static randomIv()`（0~31），六项 `getXxxIv()` IV 语义别名（§2.5）
- **Species**：`extraLearnable` 字段 + `getLearnableMoves()`（出生技@1 ∪ learnSchedule ∪ 追加条目，只读）+ `addLearnableMove`
- **Player**：`isPartyFull` / `getPartySize` / `getActiveIndex` / `addPokemon` / `switchActive` / `getHealthyPokemon` / `isPartyAllFainted`
- **Pokemon**：构造新增 `uuid`（UUID 随机）、`ivs`（Stats.randomIv）、`nature`（默认 HARDY）、`status`（默认 NONE）；新增 `getUuid` / `getIvs` / `getNature` / `getStatus` / `setStatus` / `hasMove(String)` / `canLearnMove` / `gainExp` / `fullHeal`（§2.11）

## 三、保留现状的取舍（不破坏既有调用面）

1. **技能满 4 格学招**：保留「手动决定学招」队列语义（`pendingLearnChoices` + `decideLearn`），未按"满了丢弃"或"满了覆盖"改动 —— 由 UI/控制层决定。
2. **`Player.getActive()` 返回 `Pokemon` 而非 `Optional<Pokemon>`**：契约 §2.12 用 Optional，但现有 BattleView/MainView/BattleConsole/SmokeTest 全部假定非空，全面替换会破坏全部调用方，故保留原签名（`getActiveIndex` 为 -1 兜底）。
3. **`Stats` 为可变有状态对象**：BattleEngine 持有其字段引用，未按文档不可变设计重写。
4. **`Pokemon.exp` 语义**：现有"当前等级内累积、越级清零"；文档为 medium-fast 累计曲线 —— 两者无冲突，`ExperienceCalculator` 作独立组件供新场景使用。
5. **`getSpecies().getName()` 即昵称**：文档 nickname 语义与现有 `getName()` 一致，未新增 nickname 字段。
6. **异常状态/性格/IV**：字段已就位，战斗结算尚未消费（`BattleEngine` 未接入），属后续战斗模块工作。
