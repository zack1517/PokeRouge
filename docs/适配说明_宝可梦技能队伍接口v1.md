## 三、保留现状的取舍（不破坏既有调用面）

1. **技能满 4 格学招**：保留「手动决定学招」队列语义（`pendingLearnChoices` + `decideLearn`），未按"满了丢弃"或"满了覆盖"改动 —— 由 UI/控制层决定。
2. **`Player.getActive()` 返回 `Pokemon` 而非 `Optional<Pokemon>`**：契约 §2.12 用 Optional，但现有 BattleView/MainView/BattleConsole/SmokeTest 全部假定非空，全面替换会破坏全部调用方，故保留原签名（`getActiveIndex` 为 -1 兜底）。
3. **`Stats` 为可变有状态对象**：BattleEngine 持有其字段引用，未按文档不可变设计重写。
4. **`Pokemon.exp` 语义**：现有"当前等级内累积、越级清零"；文档为 medium-fast 累计曲线 —— 两者无冲突，`ExperienceCalculator` 作独立组件供新场景使用。
5. **`getSpecies().getName()` 即昵称**：文档 nickname 语义与现有 `getName()` 一致，未新增 nickname 字段。
6. **异常状态/性格/IV**：字段已就位。异常状态已于 v1.5 接入战斗结算（见 §五）；**IV 已于 v1.10 接入属性演算**（见 §十）；性格修正仍**未接入**战斗结算。

## 十二、后续补充：招式效果与能力等级变化补齐接缝搬运（2026-09-11）

**战斗服务 v1.13**（详见《接口文档_战斗服务.md》§17、§18）已在战斗模型侧落地
`Move.statChanges` 与 `MoveEffect.PROTECT / LEECH_SEED / REST`。但**新体系侧未同步**，
导致「变化类技能全部显示『但是什么也没有发生……』」——只有携带 `inflicts` 的招式能用：

| 项 | 说明 |
|---|---|
| **症状** | 经游戏真实链路（`pokemon.infrastructure.GameData` → `PokemonBattleAdapter#battleDataPort()` → 战斗引擎）出招，叫声 / 摇尾巴 / 硬邦邦 / 高速移动 **无任何能力等级变化**，守住 / 寄生种子 / 睡觉 / 天气场地招 **完全无效**，日志只剩「但是什么也没有发生……」。旧注册表（`org.example.data.GameData`）链路正常，故既有战斗测试全绿、问题被掩盖 |
| 根因（三处静默丢弃） | ① `pokemon.domain.Move` 根本没有 `effect` / `statChanges` 字段；② `pokemon.infrastructure.GameData#loadMoves` 只解析 `c[0]~c[9]`，忽略 `c[10] statChanges` 与 `c[11] effect`；③ `PokemonBattleAdapter#toBattleMove` 硬编码 `MoveEffect.NONE` 且不传能力等级变化 |
| `Move` 新增字段 | `MoveEffect effect` + `List<StatChange> statChanges`，新增 12 参最完整构造；原 8/10 参构造**保留并委托**（`NONE` + 空列表），`hasInfliction()` / `hasStatChanges()` 查询方法 |
| 新增契约类型 | `org.example.pokemon.domain.StatChange`（`record`，`Serializable`）：`Recipient{SELF,OPPONENT}` + `StatModifier` + `delta`，`MAX_DELTA = 6` 并裁剪；`parse`/`parseAll` 容忍大小写与 `-`/`_`，**拒绝 HP** 与未知能力项；`parseAll` 以 `;` 分隔多项 |

| **接缝行为变更** | `PokemonBattleAdapter#toBattleMove` 不再硬编码 `MoveEffect.NONE`：经 `toBattleEffect`（按枚举名对齐）与 `toBattleStatChanges`（按枚举名对齐，战斗模型不支持的项如 HP **忽略**）搬运 |
