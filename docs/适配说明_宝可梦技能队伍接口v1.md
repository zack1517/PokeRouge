## 二、既有类补齐（兼容签名，不改语义）

- **ElementType**：构造带色码，新增 `getColorCode()`（§2.1，CSS 色）
- **Move**：`isPhysical()` / `isSpecial()`（已有 `isStatus`）
- **MoveSlot**：`getCurrentPp` / `getMaxPp` / `isExhausted` / `usePp` / `restorePp` / `fullRestore`（保留原 use/restore/exhausted 别名）
- **Stats**：`static randomIv()`（0~31），六项 `getXxxIv()` IV 语义别名（§2.5）
- **Species**：`extraLearnable` 字段 + `getLearnableMoves()`（出生技@1 ∪ learnSchedule ∪ 追加条目，只读）+ `addLearnableMove`
- **Player**：`isPartyFull` / `getPartySize` / `getActiveIndex` / `addPokemon` / `switchActive` / `getHealthyPokemon` / `isPartyAllFainted`
- **Pokemon**：构造新增 `uuid`（UUID 随机）、`ivs`（Stats.randomIv）、`nature`（默认 HARDY）、`status`（默认 NONE）；新增 `getUuid` / `getIvs` / `getNature` / `getStatus` / `setStatus` / `hasMove(String)` / `canLearnMove` / `gainExp` / `fullHeal`（§2.11）

## 三、保留现状的取舍（不破坏既有调用面）

1. **技能满 4 格学招**：保留「手动决定学招」队列语义（`pendingLearnChoices` + `decideLearn`），未按"满了丢弃"或"满了覆盖"改动 —— 由 UI/控制层决定。
2. **`Player.getActive()` 返回 `Pokemon` 而非 `Optional<Pokemon>`**：契约 §2.12 用 Optional，但现有 BattleView/MainView/BattleConsole/SmokeTest 全部假定非空，全面替换会破坏全部调用方，故保留原签名（`getActiveIndex` 为 -1 兜底）。
3. **`Stats` 为可变有状态对象**：BattleEngine 持有其字段引用，未按文档不可变设计重写。
4. **`Pokemon.exp` 语义**：现有"当前等级内累积、越级清零"；文档为 medium-fast 累计曲线 —— 两者无冲突，`ExperienceCalculator` 作独立组件供新场景使用。
5. **`getSpecies().getName()` 即昵称**：文档 nickname 语义与现有 `getName()` 一致，未新增 nickname 字段。
6. **异常状态/性格/IV**：字段已就位，战斗结算尚未消费（`BattleEngine` 未接入），属后续战斗模块工作。

## 六、后续补充：战斗模块改为「只消费」数据（2026-09-10）

战斗模块不再内建数据、也不再直接依赖数据源，新增只读数据端口
`org.example.battle.BattleDataPort`（**战斗服务 v1.6**，详见《接口文档_战斗服务.md》§11）。
数据侧的分工调整如下（对既有契约**无破坏性变更**）：

| 项 | 说明 |
|---|---|
| 端口方法 | `findMove(String)` / `findSpecies(String)` / `wildSpeciesPool()` / `createPokemon(String, int)`（默认实现按种族首批技能生成个体） |
| 数据模块适配器 | `org.example.data.GameDataBattleDataPort`：把数据注册表 `GameData` 适配为端口（不改 `GameData` 既有 API） |
| 组装层注入 | `org.example.integration.PokemonBattleAdapter#battleDataPort()` 为统一入口；`MainController` 与 `demo.BattleConsole` 在此注入 |
| 战斗模块约束 | `org.example.battle` 包内不出现数据文件/内建数据表，也不引用 `org.example.data` |
| 道具 | 不属于端口：`useItem(Item)` 只消费调用方传入的实例，道具来源由组装层决定 |

> 该调整**不影响**宝可梦系统的对外契约（`PokemonService` 等）；升级学招与进化现在经端口查询，
> 数据来源仍是同一份数据注册表，行为与 v1.5 一致。

> 变更已通知 UI 模块（`docs/接口文档_UI模块.md` v0.1.6）。

## 七、后续补充：战斗模块职责收敛为「演算 + 结算」（2026-09-10）

战斗模块进一步收敛，把不属于演算/结算的**野生遭遇生成**移出模块
（**战斗服务 v1.7**，详见《接口文档_战斗服务.md》§12），对既有契约**无破坏性变更**：

| 项 | 说明 |
|---|---|
| 迁出内容 | `BattleServices#wildLevelAround(int)` 与 `randomWild(int[, BattleDataPort])` |
| 新位置 | `org.example.integration.WildEncounter`（组装/流程侧）：`levelAround(...)`、`randomWild(...)` |
| 随机源 | 遭遇侧与战斗引擎侧**均不再使用 `Math.random()`**，统一为可注入的 `java.util.Random`（遭遇侧另有 `ThreadLocalRandom` 缺省重载） |
| 数据来源 | 不变：仍只经 `BattleDataPort` 取野生池与生成个体，数据模块无需改动 |
| 战斗模块约束 | `org.example.battle` 包内不出现 `Math.random()`，也不含遭遇生成逻辑；`BattleServices` 收敛为纯工厂 |
| 调用点 | `MainController#startRandomBattle()`、`demo.BattleConsole#oneWildBattle()` 改调 `WildEncounter` |

> 数据模块的适配器（`GameDataBattleDataPort`）与数据注册表 `GameData` **完全不受影响**。

> 变更已通知 UI 模块（`docs/接口文档_UI模块.md` v0.1.7）。

## 八、后续补充：道具目标选择（2026-09-10）

战斗模块的道具使用由「只能作用于出战精灵」扩展为**可指定队伍任意精灵**
（**战斗服务 v1.8**，详见《接口文档_战斗服务.md》§3.2、§10.6），属**新增重载**、
不破坏既有契约：

| 项 | 说明 |
|---|---|
| 新增接口 | `BattleService#useItem(Item, int partyIndex)`：作用于队伍中指定下标的精灵（含替补） |
| 兼容处理 | 原 `useItem(Item)` 降为 `default` 方法（等价于 `useItem(item, 出战精灵下标)`），既有调用点**零改动** |
| 道具类别 | 不新增类别：仍沿用 `org.example.model.ItemCategory` 的 `HEAL` / `CURE` / `POKE_BALL` |
| 目标规则 | 下标越界 → 提示且不消耗回合；`HEAL` 对已倒下精灵无效（不能以此复活）；`CURE` 对已倒下精灵仍有效；`POKE_BALL` 忽略目标 |
| 数据来源 | 不变：道具仍是调用方传入的实例，不经 `BattleDataPort`；数据模块与 `GameData` **无需改动** |
| 消费方同步 | `BattleController`（两步菜单：选道具 → 选目标）、`BattleView#showTargetMenu`、`demo.BattleConsole#doItem` |

> 变更已通知 UI 模块（`docs/接口文档_UI模块.md` v0.1.8）。
