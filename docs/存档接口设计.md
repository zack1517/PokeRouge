# 存档系统接口文档

> 版本：v1.3 · 日期：2026-09-10 · 模块：存档系统（Save System）
> 角色：存档系统负责人 · 状态：**待组长评审**
> 依据：dev 数据注册表 `org.example.data.GameData`（物种/道具按 id 重建）；《宝可梦、技能、队伍接口文档》§3.3（PokemonState）
> 依赖方：UI / 主循环、游戏流程模块、养成模块（战斗系统经 feature/battle 独立演进）

## 1. 概述

### 1.1 模块定位

存档系统负责**世界状态（一名玩家的队伍 + 背包 + Run 推进状态）的捕获、编解码、磁盘读写与恢复**。目标场景：

- **世界存档**：队伍内每只宝可梦（物种 id、等级、当前 HP）+ 出战位 + 背包（道具 id、数量）+ 训练家名，对战之外随时保存/读取。
- **Run 存档（v2 新增）**：把游戏流程的推进状态（段号、剩余 AP、金币、剧情线标记、里程碑标记、抓捕账本、当前可选节点、商店货架、结局）一并落盘，实现「关掉游戏再打开，进度不丢」。

> 本模块只保存「玩家对象 + Run 快照」层面的世界状态，**不保存对局过程**（回合、天气、轮换标记等归战斗模块）。流程侧同样不落盘「待结算战斗」（`FlowController.pendingFight`）——读档后从该节点的入口重新开始即可。

### 1.2 对外提供的服务

| 服务 | 说明 | 使用方 |
|------|------|--------|
| 世界存档捕获/恢复 | `org.example.model.Player` 采样 → `World`；`World` → 重建 `Player` | UI、游戏流程 |
| 文件编解码与 IO | 自定文本格式 ↔ 内存对象；UTF-8 磁盘读写 | 全部上层 |

### 1.3 设计约束

- 纯 JDK 17 实现，**不引入 JSON 等第三方序列化依赖**。
- 运行在 **dev 的 `org.example` 对象模型**上：捕获/恢复的对象是 `Player`（及其 party/bag）。存档只存「id + 可变状态」，种族 / 招式由注册表按 id 重建（格式稳定、体积小）。
- 只依赖 `org.example` 的公共 API，**不修改 org.example / dev 任何文件**。
- 包位置：`com.bao01.save`（实现文件：`SaveData.java`、`SaveManager.java`、`SaveException.java`、`SaveDemo.java`）。
- 自测入口：`com.bao01.save.SaveDemo`（无头可运行，不依赖 UI；Run 相关用例会调用游戏流程模块）。
- **验收窗口**：`com.bao01.app.RougeLauncher` / `RougeApp`（可点击的存档 + 流程演示界面，见 §6.4）。它同样只复用 `org.example` 的公共 API，仍然**不修改 `org.example` / dev 的任何文件**。

## 2. 数据模型（Model）

> 全部数据模型为不可变 `record`，定义于 `com.bao01.save.SaveData` 内；仅用于「落盘 / 传输」，不承载行为。

### 2.1 SaveData（存档数据容器）

```java
package com.bao01.save;

public final class SaveData {

    public static final int FORMAT_VERSION = 2;        // 当前存档格式版本（1 = 队伍/背包；2 = +训练家名 +Run）

    /** 恢复玩家时使用的默认训练家名。 */
    public static final String DEFAULT_PLAYER_NAME = "训练家";

    private SaveData() { }                             // 纯容器，禁止实例化
}
```

### 2.2 World（世界存档 · 顶层）

```java
public record World(int version, PlayerData player, RunSummary run) {

    public World(int version, PlayerData player) { this(version, player, null); }   // v1 兼容

    public boolean hasRun();                            // run != null
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `version` | `int` | 格式版本号，读入高于 `FORMAT_VERSION` 时拒绝加载 |
| `player` | `PlayerData` | 玩家快照（队伍 + 出战位 + 背包 + 训练家名，必填） |
| `run` | `RunSummary` | Run 快照（流程推进状态）；v1 旧档为 `null`（`hasRun() == false`） |

> `World` 是存档系统与游戏流程模块之间**唯一的耦合点**：`RunSummary` 定义在 `com.bao01.flow`，由流程模块负责语义，存档模块只做「原样搬运」。字段清单见《游戏流程接口设计文档》§2.6。

### 2.3 PartyEntry（宝可梦快照）

```java
public record PartyEntry(String speciesId, int level, int currentHp) {

    // 采样：运行态 → 数据
    public static PartyEntry capture(Pokemon p);

    // 重建：数据 → 运行态（未知物种返回 null）
    public Pokemon restore();

    public String describe();
}
```

- `speciesId`：物种 id（`s_*`），由 `GameData` 注册表按 id 重建（含种族/招式）。
- `level`：等级；`currentHp`：当前 HP，`0` 表示濒死。
- `restore()`：`GameData.instance().createPokemon(speciesId, level)` 生成满状态个体后按 `min(hp, maxHp)` 截回当前 HP。
- 能力阶级（stages）不再落盘：当前 `org.example.model.Pokemon` 尚无阶级字段，需要时再按 §6.2 追加。

### 2.4 ItemEntry（道具快照）

```java
public record ItemEntry(String itemId, int count) {

    public static ItemEntry capture(ItemStack stack);   // stack.getItem().getId() / getCount()
    public Item restore();                               // GameData.instance().item(itemId)；未知 id 返回 null
}
```

> 以 **id** 保存、按 `GameData.item(id)` 解析回注册表实例。`Bag` 以实例为键计数（每堆叠一个 `ItemStack`）。

### 2.5 PlayerData（玩家快照）

```java
public record PlayerData(List<PartyEntry> party, int activeIndex, List<ItemEntry> bag, String name) {

    public PlayerData(List<PartyEntry> party, int activeIndex, List<ItemEntry> bag) {
        this(party, activeIndex, bag, null);             // v1 兼容：无训练家名
    }

    public static PlayerData capture(Player player);     // 全队采样 + 非空背包堆叠采样 + 训练家名
    public Player restore();                             // 用存档里的名字；为空则 DEFAULT_PLAYER_NAME
    public Player restore(String playerName);            // 显式覆盖名字
}
```

- `party`：按队伍存储顺序排列（1~6 只）。
- `activeIndex`：当前出战位；恢复时若指向濒死/越界则 `leadWithFirstHealthy()` 回退到第一只存活成员。
- `bag`：背包内每种道具及其数量。
- `name`：训练家名（v2 新增）。空白串归一为 `null`；v1 旧档读出的也是 `null`。
- `restore()`：`new Player(名字)` → `addToParty` 逐只重建 → `getBag().add(item, count)` 回填背包；未知物种/道具的条目跳过，**全员不可恢复时抛 `SaveException`**。
- `restore(String)` 为**显式覆盖**语义（调用方指定名字），与 `restore()` 的「沿用存档」不同。

### 2.6 运行态对象（不序列化 · 归属 dev 的 org.example）

存档捕获/恢复针对以下 dev 公共类型（签名以 dev 实际代码为准）：

- `org.example.model.Player`：`getParty()`（只读 List）、`addToParty(Pokemon)`、`getActiveIndex()`、`setActive(int)`、`leadWithFirstHealthy()`、`healParty()`、`getBag()`。
- `org.example.model.Pokemon`：`getSpecies().getId()`、`getName()`、`getLevel()`、`getCurrentHp()`、`getMaxHp()`、`takeDamage(int)`、`heal(int)`、`isFainted()`。
- `org.example.model.Item` / `ItemStack`（`getItem()` / `getCount()` / `isEmpty()`）。
- `org.example.data.GameData`：`instance()`、`item(String id)`、`createPokemon(String id, int level) → Optional<Pokemon>`。

## 3. 注册表与恢复机制（Rebuild）

> 存档不落盘静态数据，恢复依赖 dev 的 `GameData` 注册表「按 id 重建」。

### 3.1 GameData（物种 / 道具注册表 · dev 提供）

```java
package org.example.data;

public final class GameData {
    public static GameData instance();

    /** 按道具 id 取注册表唯一实例；未知 id 返回 null。 */
    public Item item(String id);

    /** 按物种 id 与等级生成一只基础宝可梦（满 HP）；未知 id 返回 Optional.empty。 */
    public Optional<Pokemon> createPokemon(String id, int level);

    /** 图鉴收录的全部物种 / 道具。 */
    public List<Species> allSpecies();
    public List<Item> allItems();
}
```

> 数据源为 dev 的 `src/main/resources/data/species.csv` 与 `items.csv`；物种/道具 id 形如 `s_fire_cat`、`i_potion`。

### 3.2 恢复流程

```
读取存档文本
  → World（校验 version ≤ FORMAT_VERSION）
    → player.restore()
        GameData.createPokemon(speciesId, level) → 还原 HP（截回 maxHp）→ addToParty
        背包 GameData.item(itemId) → player.getBag().add(item, count)
        activeIndex 有效且非濒死 → setActive；否则 leadWithFirstHealthy()
```

## 4. 服务接口（Service）

### 4.1 SaveManager（存档服务门面）

```java
package com.bao01.save;

import org.example.model.Player;
import java.nio.file.Path;

public final class SaveManager {

    // ============ 捕获（Player → World） ============
    /** 世界存档：玩家队伍 + 背包（不含 Run 状态）。 */
    public static SaveData.World captureWorld(Player player);

    /** 完整世界存档：玩家 + Run 快照（推荐用法）。 */
    public static SaveData.World captureWorld(Player player, RunSummary run);

    // ============ 恢复（World → Player） ============
    public static Player restorePlayer(SaveData.World world);
    public static Player restorePlayer(SaveData.World world, String playerName);

    // ============ 编解码 ============
    public static String toText(SaveData.World world);
    public static SaveData.World fromText(String text);

    // ============ 磁盘 IO ============
    public static Path defaultPath();                 // {user.home}/.bao01/save.txt
    public static boolean defaultSaveExists();        // 默认路径上是否已有存档（UI 用来决定「读取」按钮是否可用）
    public static void writeToFile(Path path, SaveData.World world);   // 自动建父目录
    public static SaveData.World readFromFile(Path path);
}
```

### 4.2 SaveException（存档异常）

```java
package com.bao01.save;

/** 读写 / 解析 / 恢复失败时抛出的运行时异常。 */
public class SaveException extends RuntimeException {
    public SaveException(String message);
    public SaveException(String message, Throwable cause);
}
```

## 5. 存盘文件格式（Codec）

- 编码：UTF-8；首行魔数 `BAO01SAVE`。
- 解析时忽略空行与 `#` 注释行；标记错位 / 字段不足 / 数字非法 / 枚举值非法均抛 `SaveException` 并携带行内容。

### 5.1 标记一览

| 行前缀 | 引入版本 | 含义 | 示例 |
|--------|---------|------|------|
| `VERSION` | v1 | 格式版本 | `VERSION 2` |
| `NAME` | v2 | 训练家名（**可选**，缺省则不写该行） | `NAME 小红` |
| `PT` | v1 | 队伍头（成员数 + 出战位） | `PT 2 0` |
| `POKE` | v1 | 宝可梦：物种id｜等级｜当前HP | `POKE s_fire_cat|50|45` |
| `BAG` | v1 | 背包条目数 | `BAG 1` |
| `ITEM` | v1 | 道具：道具id｜数量 | `ITEM i_potion|2` |
| `RUN` | v2 | Run 头：段号 剩余AP/上限 金币 阶段 必然节点 结局 | `RUN 1 6/6 500 ROUTE NONE PLAYING` |
| `STORY` | v2 | 剧情线 6 个布尔（1/0）：火箭队入场｜已遇神兽｜持有大师球｜首领已败｜冠军已败｜侵略结束 | `STORY 0 0 0 0 0 0` |
| `FLAGS` | v2 | 里程碑 5 个布尔：道馆重试｜四天王通过｜四天王重试｜冠军通过｜侵略通过 | `FLAGS 0 0 0 0 0` |
| `CAUGHT` | v2 | 抓捕账本条目数 | `CAUGHT 1` |
| `CATCH` | v2 | 抓捕记录：精灵名｜累计次数 | `CATCH 焰尾狐|2` |
| `OPTIONS` | v2 | 本段可选节点数 | `OPTIONS 2` |
| `OPTION` | v2 | 可选节点：种类｜AP消耗｜必然(1/0)｜展示文案 | `OPTION WILD|1|0|野生的 焰尾狐` |
| `SHOP` | v2 | 商店货架条目数 | `SHOP 0` |
| `OFFER` | v2 | 货架项：道具id｜价格｜说明 | `OFFER i_potion|150|回复 20 HP` |

> `RUN` 行的 `阶段` 取值 `ROUTE`（常规路线）/ `FINAL`（终局）；`必然节点` 取值 `NONE` 或 `NodeType` 名；`结局` 取值 `PLAYING`（进行中）或 `Ending` 名。三者均由流程模块的 `Ending.textOf` / `NodeType.textOf` / `Ending.parse` / `NodeType.parse` 负责，存档模块不解释其语义。

### 5.2 完整示例（v2）

```
BAO01SAVE
VERSION 2
NAME 小红
PT 2 0
POKE s_fire_cat|50|45
POKE s_water_tad|48|44
BAG 1
ITEM i_potion|2
RUN 3 0/8 1234 ROUTE GYM PLAYING
STORY 1 1 1 1 1 1
FLAGS 1 1 0 0 0
CAUGHT 2
CATCH 焰尾狐|2
CATCH 水箭龟|1
OPTIONS 2
OPTION WILD|1|0|野生的 焰尾狐
OPTION GYM|2|1|道馆战
SHOP 1
OFFER i_potion|150|回复 20 HP
```

### 5.3 版本历史

| 版本 | 变更 | 兼容性 |
|------|------|--------|
| v1 | `VERSION` / `PT` / `POKE` / `BAG` / `ITEM` | — |
| v2 | 新增可选 `NAME` 行与 `RUN`/`STORY`/`FLAGS`/`CAUGHT`/`CATCH`/`OPTIONS`/`OPTION`/`SHOP`/`OFFER` 段 | **v2 解析器可读 v1 旧档**（`name = null`、`run = null`）；v1 解析器读 v2 档会被版本号拦住 |

## 6. 健壮性、扩展与验证

### 6.1 健壮性

| 场景 | 行为 |
|------|------|
| 版本号高于当前 | 拒绝加载（防旧客户端读新档） |
| 未知物种 / 道具 | 跳过该项；全部成员不可恢复才抛异常 |
| 出战位濒死 / 越界 | `leadWithFirstHealthy()` 回退第一只存活成员 |
| 文件缺失 / 标记错位 | 抛 `SaveException`（含路径或行内容） |

### 6.2 向后兼容扩展

- 新增字段按「末尾追加 + 可选默认值」设计；`FORMAT_VERSION` 需要时递增。
- 预留给未来的扩展点：能力阶级（stages）、个体值（IV）、技能 PP、携带道具、异常状态等——只需给 `PartyEntry` 增字段并升级版本。

### 6.4 验收窗口（可点击的存档 + 流程演示）

为验证「存档系统 + 游戏流程」在真实交互下可用，本模块附带一个独立 JavaFX 窗口：

- 入口：`com.bao01.app.RougeLauncher` → `com.bao01.app.RougeApp`。
- **已作为工程默认启动入口**：`pom.xml` 的 `javafx-maven-plugin` 通过属性 `<javafx.mainClass>` 指向本窗口，因此 **IDEA 里点 Run（运行配置 `bao01 [javafx:run]`）或 `mvn javafx:run` 直接进入本窗口**。
- 仍然只读调用 `org.example` 的公共 API（`GameData`、`Player`/`Pokemon`/`Bag`、`BattleServices`、`BattleController`），**不修改 `org.example` 任何文件**。

界面分区与可执行动作：

| 区域 | 内容 / 动作 |
|------|------------|
| 顶部 | 段号、AP、金币、阶段、结局、必然节点、抓捕累计 |
| 左栏 | 队伍（点击成员 = 设为先发）、背包（道具 × 数量） |
| 中栏 | 本段可选节点按钮、必然节点按钮、医院、商店货架（可买）、剧情线 / 抓捕记录 |
| 右栏 | 操作日志（保留最近 400 行） |
| 底部 | **保存游戏** / **读取游戏** / **新 Run** / **退出**（显示存档完整路径） |

运行方式：

```bash
# A. 推荐：IDEA 里直接点 Run（选运行配置 "bao01 [javafx:run]"）
#    改动 pom 后如未生效，在 Maven 面板点一次 Reload / 重新加载项目。

# B. 命令行
mvn clean compile
mvn javafx:run

# C. 启动 dev 的主界面（org.example.App）：用 -D 覆盖入口属性即可
mvn javafx:run -Djavafx.mainClass=org.example.Launcher

# D. 不使用 Maven 插件时（classpath 需含 JavaFX 17 的平台 jar）
java -Dfile.encoding=UTF-8 -cp "target/classes;<javafx-base|graphics|controls|fxml>-17.0.20-win.jar" \
     com.bao01.app.RougeLauncher
```

> 入口用属性 `javafx.mainClass` 而非写死类名，是为了让「点 Run 进存档+流程窗口」与「切回 dev 主界面」都只需改一处；合并回 dev 分支时如与 dev 的入口配置冲突，改这一行属性即可。

存档落在 `SaveManager.defaultPath()`（`{user.home}/.bao01/save.txt`）；窗口启动时会打印格式版本与路径。「读取游戏」按钮在存档不存在时自动置灰。

**已知简化（验收时可接受，正式接入主界面时需处理）：**

1. `org.example` 的战斗引擎是 **1v1**，而流程的「路人 / 道馆 / 四天王…」会构造 2~4 只敌方队伍；本窗口**只取第一只**开打，其余对手在日志中说明。
2. 战斗引擎判定「捕捉成功」时，窗口额外调用一次 `FlowController.attemptCatch(Pokemon)` 记入抓捕账本（是否算流程内的合法捕获沿用流程侧规则）。
3. **随机源不落盘**：读档后 `FlowController.restored(...)` 使用新的 `RandomSource`，因此读档之后的随机序列与「不关游戏继续玩」不完全一致（存档字段本身是精确的）。
4. 若在战斗未结束时退出战斗界面，本场保持「待结算」；再次进入该节点即可重开。
