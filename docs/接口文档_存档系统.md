# 存档系统接口文档（存档系统）

> 版本：v2.5 · 日期：2026-09-14 · 模块：`org.example.save`（PokeRouge）

本模块交付「单机 4 存档位 + 未作战时可存档」的完整实现：进度快照的文件布局、文本格式、
精灵映射、编排入口，以及启动页 / 主菜单 / 存档位选择页的接线方式。

**v2.5 相对 v2.4 的变化**（**`save.txt` 的文件格式与 `FORMAT_VERSION` 完全未变**，
只改「怎么用档位」，因此**旧档全部可直接沿用**）：

| 变化 | 说明 |
| --- | --- |
| **新增 `save.prev.txt`（上一个存档点）** | `SaveStore#write` 在**进度真的变了**时，先把旧的 `save.txt` 备份成同目录的 `save.prev.txt`（只保留最近一份），再原子写出新进度 |
| **支持「回退一步」（SL 大法）** | `SaveStore#rollbackToPrevious(slot)` 用备份覆盖 `save.txt` 并删除备份；`SaveManager#loadPrevious(slot)` 从备份重建会话。读档页（`CONTINUE`）卡片上多一个「回退一步」次级按钮 |
| **同一档位可反复游玩** | `SaveManager#newRun(slot, name, starter)`：**只清进度快照**（`deleteProgress`，即 `save.txt` + `save.prev.txt`），**保留图鉴成长**，在同一档位开新一轮 |
| **档位列表标出本轮已结束** | `SaveSummary` 增 `gameOver` / `cleared` 与 `finished()` / `finishedText()`，`SlotStatus` 增 `hasPrevious` / `canRollback()` / `finished()` |
| **已结束的档位改为引导开新一轮** | `loadFromSlot()` 不再硬拒绝「本轮已结束」的档位，改为弹「开始新一轮 / 取消」引导；确认后**跳过再选档位**直接进选初始精灵页 |
| **另存档位时图鉴成长一并搬迁** | `SaveManager#save` 在写快照之外，把当前图鉴成长写到**目标档位**并重绑自动落盘 —— 否则另存后成长仍会回流到原档位 |

**v2.3 相对 v2.2 的变化**（**存档层代码与文件格式完全未变**，只补界面接线与流转）：

| 变化 | 说明 |
| --- | --- |
| 主菜单新增「**读取存档**」 | `MainView.Actions#onLoadGame()` → `MainController#showLoadSelection()` 复用 `Purpose.CONTINUE` 选档页；战斗中被拒绝 |
| 主菜单「退出游戏」→「**返回主界面**」 | `onExit()` 不再 `Platform.exit()`，改为 `returnToStartScreen()`（先 `autoSave` 再释放会话回启动页）；真正退出仍只由窗口关闭按钮的二次确认负责 |
| **一轮远征结束回启动页** | `finishRogueRun()`（通关 / 战败）与队伍全灭都不再停在主菜单，改为 `returnToStartScreen()`，玩家在启动页「开始游戏」开新档或「继续游戏」读档 |
| **已结束的一轮不再可载入** | `loadFromSlot()` 在 `session.isRogueRunFinished()` 时提示「本轮已结束」并留在选档页（局内读档不动当前进度，启动页进来的直接回启动页），避免载进入一个没有内容的死档（**v2.5 起改为引导在同一档位开新一轮**） |

**v2.1 相对 v2.0 的变化**（跟随《需求文档》§五「火箭队剧情线与神兽偶遇」，**格式版本仍为 2**）：
新增可选 `STORY` 键，记录火箭队剧情线与神兽偶遇的五个状态标记；旧 v2 与 v1 文件缺该行时按
「剧情线未开启」读回。

**v2.0 相对 v1.0 的变化**（跟随《需求文档》§4「路线节点 / 行动点」改版）：

| 变化 | 说明 |
| --- | --- |
| `FORMAT_VERSION` | `1` → **`2`** |
| `RUN` 行 | 从 `楼层 / 点数 / 是否结束`（3 字段）改为 **7 字段**：行动点 / 上限 / 推进阶段 / 重试次数 / 金币 / 是否结束 / 是否通关 |
| `OPTION` / `BOSS` 行 | 各增 1 个字段「**是否已走过**」；`BOSS` 语义由「本层首领」改为「**本段必然节点**（道馆 / 四天王 / 冠军 / 首领侵略战）」 |
| `STORY` 行 | **新增可选键**（5 个 `0\|1` 标记）：火箭队剧情线是否开启 / 首领是否已击败 / 神兽是否已偶遇 / 是否有待触发的 0 点神兽 / 首领侵略战是否已触发；全 `false` 时不写此行 |
| `SaveSummary` | `currentFloor` 拆为 **`ap` + `gold`** 两个字段 |
| 旧档兼容 | **v1 存档仍可读取**，自动迁移为行动点语义（见 §6）；**无 `STORY` 行的 v2 文件**按「剧情线未开启」读回 |

## 1. 需求与范围

| 需求 | 落地方式 |
| --- | --- |
| 单机游戏提供 **4 个存档位** | `SaveSlot` 固定 4 个枚举值，`slot1 ~ slot4` 即磁盘目录名 |
| **未作战时**可存档 | 主菜单「保存游戏」（手动）+ 回到主菜单 / 通过节点后（自动）；战斗中 `MainController` 拒绝手动存档 |
| **未作战时**可读档 | 启动页「继续游戏」与主菜单「读取存档」都进 `CONTINUE` 选档页；战斗中读档与回退都被拒绝 |
| 每个档位**各自独立** | 每档一份进度快照 + 一份图鉴成长，互不影响（含个体值加成） |
| 关掉游戏后再打开能继续 | 全部落在用户主目录，重新构建工程不丢档 |
| **支持「SL 大法」** | 每次**进度真的变化**时保留上一份进度为 `save.prev.txt`；读档页「回退一步」可退回上一个存档点（只留一步，不做无限存档历史） |
| **同一档位反复游玩** | 一轮结束（通关 / 战败）后可在**同一档位**开新一轮：只重置远征进度，**保留**该档位的图鉴成长 |
| 一轮结束（通关 / 战败 / 队伍全灭）后**回启动页** | `finishRogueRun()` 落盘后回启动页（不退出程序）；「继续游戏」里该档位显示「开始新一轮」，选定后询问是否在**该档位**开新一轮，也可以改选别的档位或先「回退一步」 |

**不做**：云存档、跨档位共享图鉴、存档压缩加密、跨版本自动迁移（版本不符一律明确报错）、
多份历史存档点的「存档树 / 无限回溯」。

## 2. 磁盘布局

根目录由 `SaveStore#defaultRoot()` 给出：`<user.home>/.pokerouge/saves`。

```
<user.home>/.pokerouge/saves/
├── slot1/
│   ├── save.txt                 # 进度快照（本模块 SaveCodec 格式）
│   ├── save.prev.txt            # 上一个存档点（「回退一步」用；只保留最近一份）
│   └── growth-progress.txt      # 该档位的图鉴成长（沿用成长模块既有格式）
├── slot2/ …
├── slot3/ …
└── slot4/ …
```

- **目录名即档位 id**：`SaveSlot#id()` 一经发布**不可更改**，否则玩家已有存档会找不到。
- **`save.prev.txt` 是「上一个存档点」**：`SaveStore#write` 在写出新进度**之前**，先把旧的
  `save.txt` 复制成 `save.prev.txt`（覆盖上一份，因此只留一步）。判定「进度是否变化」的是
  `SaveCodec#sameProgress`，它**忽略 `SAVED_AT` 行**后逐字比较 —— 否则「回到主菜单」这类
  **内容没变的自动存档**会把上一个存档点推成同一份进度，回退一步就等于没退。
  首次写入（本来没有 `save.txt`）不会产生备份，因此新档的「回退一步」按钮是灰的。
- `save.prev.txt` 的存在只影响「回退一步」是否可用（`SlotStatus#canRollback()`）：
  **没有它照样能正常读档**，档位状态（`exists` / `usable`）只看 `save.txt`。
- 写盘为**原子写**：先写 `*.tmp` 再 `Files.move(ATOMIC_MOVE)`，不支持时退化为 `REPLACE_EXISTING`。
  Windows 上目标文件被索引器/杀毒软件短暂占用会让替换以共享冲突失败，因此替换**带短间隔重试**
  （3 次 × 20ms），仍失败才报错 —— 避免对玩家弹一个假的「保存失败」。
  失败路径会清理临时文件，存档目录不会残留 `*.tmp`。备份失败**只记日志不抛**（回退能力可降级，
  但保存本身绝不能被备份拖垮）。
- 目录不存在时自动创建（首次运行、玩家手工删过目录都能恢复）。
- 测试一律使用 `new SaveStore(tempDir)` 注入临时根目录，不触碰开发者本机存档。

## 3. 文件格式（`save.txt`）

纯文本，**每行一条记录**：`键|值1|值2…`。项目不引入 JSON 库，因此采用这种便于人工查看与
手改的格式。

```
# PokeRouge 存档 v2
# 格式：键|值…（正文中的 | 与换行会被反斜杠转义）
VERSION|2
SAVED_AT|1700000000000
PLAYER|小明
ACTIVE|0
SEGMENT|2
MAP|map/forest.png
RUN|4|10|EXPLORING|0|320|0|0
PP|bulbasaur|12|31|20|15|10|5|0|340|POISON|2|3|1|27
MOVE|0|0|tackle|30
MOVE|0|1|vine-whip|7
ITEM|i_potion|3
OPTION|野生遭遇|WILD|0|遇到一只野生精灵；本次遭遇不消耗行动点|1
OPTION|宝可梦医院|HOSPITAL|1|治疗全队伤病与 PP、复活濒死宝可梦|0
BOSS|第 2 段道馆战|GYM|0|行动点耗尽后必然触发，是本段的进度门槛|0
STORY|1|0|1|0|0
```

| 键 | 字段 | 说明 |
| --- | --- | --- |
| `VERSION` | 1 个 | 格式版本，**必填**；缺失或高于 `SaveData.FORMAT_VERSION` 抛 `SaveFormatException` |
| `SAVED_AT` | 1 个 | 存档时间（epoch millis），档位列表展示用 |
| `PLAYER` | 1 个 | 训练家名；空白时读档回落为「训练家」 |
| `ACTIVE` | 1 个 | 出战（先发）精灵在队伍中的下标 |
| `SEGMENT` | 1 个 | 地图段号；**`0` 表示尚未开始远征**，读档时原样保留（`<0` 归 0） |
| `MAP` | 1 个 | 当前段地图背景 classpath；**无此行为 null**（可选键，不写占位符） |
| `RUN` | 7 个 | `ap / apMax / phase / retryUsed / gold / gameOver(0\|1) / cleared(0\|1)`；`phase` 取 `RoutePhase` 名（无法识别时按 `EXPLORING`） |
| `PP` | 15 个 | 精灵：`speciesId / level / ivHp / ivAtk / ivDef / ivSpA / ivSpD / ivSpd / exp / status / sleepTurns / badlyPoisonCounter / confusionTurns / currentHp / heldItemId`（`heldItemId` 为 **v2.4 新增**，空串表示未携带） |
| `MOVE` | 4 个 | `队伍下标 / 技能槽序号 / moveId / 剩余PP`，按下标归并到对应精灵 |
| `ITEM` | 2 个 | `itemId / count` |
| `OPTION` | 6 个 | `name / type / cost / description / consumed(0\|1)`（本段可用路线节点；`consumed` 即「**本轮曾走过**」） |
| `BOSS` | 6 个 | 同 `OPTION`，本段**必然节点**（道馆 / 四天王 / 冠军 / 首领侵略战）；**无此行为 null** |
| `STORY` | 5 个 | `rocketLineUnlocked / rocketBossDefeated / legendaryMet / pendingLegendary / aggressionTriggered`（均为 `0\|1`）：火箭队剧情线与神兽偶遇状态（《需求文档》§五）；**五个标记全为 `0` 时不写此行**，无此行按「剧情线未开启」读回 |

解析规则：

- `#` 开头为注释，空行忽略；
- **未知键跳过**（老程序读到新版本多写的字段不会崩）；
- 正文的 `|`、`\`、换行分别转义为 `\|`、`\\`、`\n`（`\r` 丢弃），因此**一行恒为一条记录**；
- 数值字段非法时抛出的异常**带行号**，便于玩家定位手改错的地方；
- `MOVE` 行指向不存在的精灵下标时该行被忽略，不让整档报废；
- **缺字段走兜底而非报错**：`OPTION`/`BOSS` 缺第 6 字段时 `consumed = false`；`RUN` 只有 3 个字段时
  按 v1 旧档处理；`STORY` 缺字段按 `0`（`false`）处理；`PP` 缺第 15 字段（v2.4 之前写出的旧档）
  按**未携带装备**读回（见 §6）。
- **`save.prev.txt` 与 `save.txt` 格式完全相同**（它就是一份旧 `save.txt` 的原样副本），
  因此回退后玩家看到的一切与那一刻完全一致，无需任何迁移或特殊解析。

## 4. 公开 API

### 4.1 `SaveSlot`（`org.example.save`）

| 成员 | 返回 | 说明 |
| --- | --- | --- |
| `SLOT_1 … SLOT_4` | — | 四个档位常量 |
| `id()` | `String` | `slot1 ~ slot4`，即磁盘目录名 |
| `displayName()` | `String` | `存档 1 ~ 存档 4`，界面标题 |
| `all()` / `count()` | `List<SaveSlot>` / `int` | 全部档位（顺序 1→4）/ 数量（4） |
| `ofId(String)` | `Optional<SaveSlot>` | 按 id 反查；未知 id 或 null 返回空 |
| `toString()` | `String` | 返回中文展示名（日志与界面统一） |

### 4.2 `SaveStore`

| 方法 | 说明 |
| --- | --- |
| `SaveStore(Path root)` / `defaultStore()` / `defaultRoot()` | 注入根目录 / 默认根目录（`<user.home>/.pokerouge/saves`） |
| `root()` / `slotDir(slot)` / `saveFile(slot)` / `growthFile(slot)` / `previousFile(slot)` | 路径查询（`previousFile` 即 `save.prev.txt`） |
| `exists(slot)` / `hasAnySave()` | 该档是否有进度（**只看 `save.txt`**） / 是否有任意档可继续 |
| `hasPrevious(slot)` | 该档是否有可回退的上一个存档点（要求 `save.txt` 与 `save.prev.txt` **同时**存在） |
| `statuses()` / `status(slot)` | 四个 / 单个 `SlotStatus`（列表渲染用） |
| `write(slot, SaveData)` | 原子写出（自动建目录）；**进度真的变了**才先把旧内容备份成 `save.prev.txt` |
| `read(slot)` | `Optional<SaveData>`；空档返回空，**内容损坏抛 `SaveFormatException`** |
| `readPrevious(slot)` | 同上，但读的是 `save.prev.txt`（「回退一步」载入用） |
| `rollbackToPrevious(slot)` | 用 `save.prev.txt` 覆盖 `save.txt` 并删除备份，返回是否真的回退；**先校验再覆盖**（见下） |
| `loadGrowth(slot)` / `createGrowth(slot)` | 载入 / 新建该档图鉴成长（接管自动落盘） |
| `writeGrowth(slot, GrowthProgress)` | 把成长写到该档位并**重绑自动落盘**（另存档位时搬迁成长用；成长已在此档则等价于刷一次盘） |
| `delete(slot)` | 同时删除 `save.txt`、`save.prev.txt` 与图鉴成长，返回是否删到文件 |
| `deleteProgress(slot)` | 只删 `save.txt` 与 `save.prev.txt`，**保留图鉴成长**（同一档位开新一轮用） |

`SlotStatus(slot, exists, readable, hasPrevious, summary)`：

- `empty()`：该档无进度文件（`summary` 为 `null`）；
- `readable()`：内容能解析出摘要（宽松，仅看关键行）；
- `usable()`：**存在且可读** —— 「继续游戏」按钮的可用条件（**已结束的一轮也算可用**，v2.5 起）；
- `canRollback()`：`exists && hasPrevious` —— 「回退一步」按钮的显示条件；
- `finished()`：`summary != null && summary.finished()` —— 按钮文案改「开始新一轮」，并参与置灰判定。

> 列表展示刻意用**宽松**的 `SaveSummary` 解析（缺行/数值非法时兜底），
> 而正式读档用**严格**的 `SaveCodec#parse`（非法即报错）。这样单个坏档不会让 4 个档位都渲染不出来。

`rollbackToPrevious` 的**顺序保证**：先 `SaveCodec#parse` 校验备份内容，**再**覆盖 `save.txt`。
备份损坏时抛 `SaveFormatException` 且**当前进度一个字节都不动** —— 否则「想回退却把现在这份也弄坏」
就成了玩家不可恢复的损失。回退**只回退进度快照**：图鉴成长属于局外数据，不参与回退。

### 4.3 `SaveSummary`

`record(slot, playerName, partySize, aliveCount, segment, ap, gold, savedAtMillis, gameOver, cleared)`，
提供 `savedAtText()`（`yyyy-MM-dd HH:mm`，时间未知返回「时间未知」）、`teamWiped()` 与
`describe()`，后者格式如：

```
小明 · 队伍 3 · 第 2 段 · 行动点 4 · 金币 320 · 2026-09-10 15:30
```

`segment == 0`（尚未开始远征）时输出「· 未开始远征」，不显示行动点与金币。

本轮结束标记（v2.5 新增）：

| 成员 | 说明 |
| --- | --- |
| `gameOver` / `cleared` | 这一轮远征是否已战败 / 已通关（由摘要解析 `RUN` 行的第 6、7 字段得到） |
| `finished()` | `gameOver \|\| cleared` —— 该档位是否已无可继续的一轮 |
| `finishedText()` | 「本轮已通关」/「本轮已战败」/ 空串（尚未结束），档位卡的角标文案 |

> 摘要解析刻意**区分 v1 / v2 的 `RUN` 行语义**：v1 的第 1 个字段是楼层（无意义），第 2 个字段才是
> 「点数」，即行动点；v2 的第 1 个字段才是行动点、第 5 个字段是金币。判据是字段个数（v1 为 3 个）。
> 结束标记在 v1 档里取 `parts[3]`（即 v1 `RUN|楼层|点数|已结束` 的「已结束」值），
> 且 `cleared` 恒为 `false`（v1 没有通关标记）；字段缺失时按「未结束」处理。`parseSummary`
> 是**宽松**解析，因此**不会**因结束标记读不出来而让整档在列表里变成损坏。

### 4.4 `SaveManager`（编排入口，UI 只需依赖它）

| 方法 | 说明 |
| --- | --- |
| `SaveManager(SaveStore)` / `defaultManager()` / `store()` | 注入仓库 / 默认仓库 |
| `snapshot(Player, GameSession)` | `SaveData` 快照（带当前时间），不落盘 |
| `save(SaveSlot, Player, GameSession)` | 手动保存：写进度快照 + **把图鉴成长写到目标档位并重绑自动落盘**；**失败抛异常**，由 UI 提示 |
| `autoSave(SaveSlot, Player, GameSession)` | 自动保存：语义同 `save`；**失败只记日志并返回 `false`**，绝不打断游戏 |
| `load(SaveSlot)` | `Optional<GameSession>`；空档 / 队伍全部失效返回空，内容损坏抛 `SaveFormatException` |
| `loadPrevious(SaveSlot)` | 同上，但读 `save.prev.txt`（「回退一步」）；**只读不写**，备份是否消耗由 `SaveStore#rollbackToPrevious` 决定 |
| `newGame(SaveSlot, String trainerName, domain.Pokemon starter)` | **清空该档**（进度 + 图鉴成长）后建立图鉴成长从零开始的会话 |
| `newRun(SaveSlot, String trainerName, domain.Pokemon starter)` | 同一档位**开新一轮**：只清进度快照（`deleteProgress`），**保留**图鉴成长 |

`save` 为什么要顺带写成长（v2.5 修复的真实缺陷）：图鉴成长的自动落盘被绑定在**某个档位的文件**上
（`GrowthProgressStore#attachSaver`），而玩家可以通过「保存游戏」把进度**另存到别的档位**。
如果换档时不把成长写过去并重绑，换档后新捕捉仍会写回**原档位**的文件，两个档位的图鉴成长就会各自为政。

`newRun` 与 `newGame` 的区别只有一处 —— **不删 `growth-progress.txt`**：

- 新会话里的 `RunData` 本来就是默认值（`RouteConfig.STARTING_GOLD`、空背包、空队伍、`segment = 0`、
  `ap = 0`、`gameOver = false`），因此金币 / 道具 / 装备 / 队伍**天然全部重置**；
- 图鉴成长是**外部带进来**的唯一跨轮数据，于是个体值加成能一轮轮攒下去，「同一档位反复游玩」才成立。

`load` / `loadPrevious` 的重建规则（这些是「读档后进度不缩水」的关键）：

- 队伍：逐只经 `PokemonMapper` 还原；**物种已不存在的精灵被丢弃**（一只都不剩时返回空，避免带空队伍进游戏）；
- 出战下标裁剪到 `[0, 队伍数-1]`；
- 背包：按 `itemId` 重建（道具已下架则跳过）；
- 图鉴成长：取自**该档位自己**的 `growth-progress.txt`（`loadPrevious` 也取这一份，**不随回退还原**）；
- 段号 / 地图背景 / 行动点 / 行动点上限 / 推进阶段 / 重试次数 / 金币 / `gameOver` / `cleared` /
  本段路线节点（含「已走过」标记）/ 必然节点逐项还原；直接写 `RunData` 字段而**不**调
  `enterSegment`，避免重抽节点或改变随机顺序。
- 段号**不经过 `GameSession#setSegment`**（后者会把 `0` 抬到 `1`），而是直接写 `RunData`，
  因此「尚未开始远征」的档读回来后仍能被 `RunData#isNotStarted()` 认出。
- **`consumed` 只是「本轮曾走过」的布尔标记**：常驻节点（路人 / 野外精灵 / 医院）走过后仍可重复
  进入，因此读档后**不因该标记置灰**；已走次数不落盘（读回后按 1 次计，仅影响界面文案）。

### 4.5 `PokemonMapper`

`toData(Pokemon)` / `toPokemon(SaveData.PokemonData) -> Optional<Pokemon>`。

- 种族与技能**按 id 重查**（优先 `org.example.pokemon.infrastructure.GameData`，
  回退 `PokemonBattleAdapter.battleDataPort()`），与战斗中新生成的精灵同源；
- 这样存档保存的是「**属于这只精灵自己的东西**」：个体值、当前 HP、经验、异常状态与其计数、
  技能剩余 PP。种族值/最大 HP 等派生值读档后现算，因此随数据表调整而自动修正。
- 越界值一律**裁剪**而非报错：等级裁到 `[1, Pokemon.MAX_LEVEL]`、当前 HP 裁到 `[0, 最大HP]`、
  技能 PP 裁到 `[0, 最大PP]`；未知物种返回空、未知技能被丢弃、缺失个体值按全 0。

`Pokemon` 与 `MoveSlot` 为此各补了一个**只读还原入口**（既有 API 无 setter）：

- `Pokemon.restore(species, level, ivs, slots, exp, status, sleepTurns, badlyPoisonCounter, confusionTurns, currentHp)`
  —— 直写私有字段，HP 与 exp 做裁剪，属性仍由 `computeStats` 现算；
- `MoveSlot(Move, int pp)` —— 按剩余 PP 构造，内部裁到 `[0, maxPp]`。

## 5. 界面接线

| 页面 | 类 | 存档相关职责 |
| --- | --- | --- |
| 启动页 | `StartView(onStartGame, onContinueGame, canContinue)` | 「继续游戏」入口；无任何存档时置灰并给出提示 |
| 存档位选择页 | `SaveSlotView` | **三种用途复用**：`NEW_GAME` / `CONTINUE` / `SAVE`；`CONTINUE` 卡片上另有「回退一步」（SL） |
| 初始宝可梦选择页 | `StarterSelectionView` | 选完初始精灵后进入 `NEW_GAME` 选档；**从「开始新一轮」进来时会跳过选档页**（见 §5.1） |
| 主菜单 | `MainView.Actions` | 「保存游戏」`onSaveGame()`、「读取存档」`onLoadGame()`、「返回主界面」`onExit()`；标题栏显示当前档位名 |

`SaveSlotView.Purpose` 决定标题文案与按钮可用性：

| Purpose | 标题 | 可选档位 | 按钮文案 |
| --- | --- | --- | --- |
| `NEW_GAME` | 选择存档位 | 全部（覆盖需二次确认） | 空档「在此开始」/ 已占用「覆盖并开始」 |
| `CONTINUE` | 继续游戏 | `usable()` 的档位（**含本轮已结束的档位**） | **本轮已结束**「开始新一轮」/ 否则「继续游戏」 |
| `SAVE` | 保存游戏 | 全部 | 当前档「保存到当前档」/ 其他档「保存并切换到此」 |

`CONTINUE` 卡片的角标与次级按钮（v2.5）：

| 元素 | 条件 | 行为 |
| --- | --- | --- |
| 角标「本轮已战败 / 本轮已通关」 | `SlotStatus#finished()`（优先于「队伍已全倒下」） | 只做提示；卡片**仍可选** |
| 按钮文案「开始新一轮」 | `SlotStatus#finished()` | 选定后由控制器询问是否在该档位开新一轮 |
| 次级按钮「回退一步」 | `purpose == CONTINUE && SlotStatus#canRollback() && onRollback != null` | 调 `MainController#rollbackSlot(slot)`（二次确认后回退） |
| 灰卡样式 | 队伍全倒下 **或** 本轮已结束 | **只是视觉提示**，与按钮可用性解耦（见下） |

> **v2.5 起「本轮已结束」的档位按钮不再禁用**：结束的一轮虽然不能「继续」，但它是**开新一轮的入口**，
> 禁用反而会让玩家找不到自己那个档位。因此 `selectable()` 在 `CONTINUE` 下对已结束档返回 `true`
> （灰卡样式仍保留，作为「没有可继续的进展」的视觉提示），而真正禁用的只剩两种情况：
> **档位为空**、**存档损坏**（`empty()` / `!usable()`）与**队伍全倒下且本轮未结束**。

`SaveSlotView` **自身不做任何 IO**：摘要文本来自 `SaveStore.SlotStatus`，
选择结果经构造参数的回调（`Consumer<SaveSlot>`）交回 `MainController`；
覆盖确认与失败提示都由控制器负责。

### 5.1 `MainController` 流程

```
启动页 ──开始游戏──► 选初始精灵 ──► 选档位(NEW_GAME) ──确认覆盖──► newGame + autoSave + 主菜单
  │
  ├──继续游戏──► 选档位(CONTINUE) ──┬─ 进行中的档 ──► load ──► 主菜单
  │                                 ├─ 本轮已结束的档 ──确认──► 选初始精灵 ──► newRun + autoSave + 主菜单
  │                                 │                            （跳过再选档位，就是这一档）
  │                                 └─ 「回退一步」──► 二次确认 ──► loadPrevious + rollbackToPrevious ──► 主菜单
  │
  └──（退出程序只走窗口关闭按钮的二次确认）

主菜单 ──保存游戏──► 选档位(SAVE) ──┬─ 当前档 ──────────────► save
                                   ├─ 其他空档 ────────────► save
                                   └─ 其他已有档 ──确认覆盖─► save
                                        （取消 → 留在选档页重选）
     save 成功 → activeSlot = 所选档位 → 主菜单（标题栏显示新档位）→ 「保存成功」提示
     save 失败 → 留在选档页（「保存失败」弹窗已给出原因）
主菜单 ──读取存档──► 选档位(CONTINUE) ──► load ──► 主菜单（换档，当前进度已先 autoSave）
主菜单 ──返回主界面──► autoSave + 释放会话 ──► 启动页（不退出程序）
主菜单 / 通过节点 ──► autoSave（静默，失败不打扰玩家）
战斗中 ──保存游戏 / 读取存档 / 回退一步──► 拒绝并提示「请先结束当前战斗」
一轮远征结束（通关 / 战败 / 队伍全灭）──► autoSave + 释放会话 ──► 启动页（在那里「继续游戏」选同一档开新一轮）
```

- 新增字段：`saveManager`（`SaveManager.defaultManager()`）、`activeSlot`（当前档位，未选档为 `null`）、
  `battleInProgress`（战斗中）、`pendingNewRunSlot`（正等待选初始精灵的「要来开新一轮」的档位，见下）；
- `enterBattle(engine, onFinished)` 统一进入战斗：进入前置 `battleInProgress = true`，
  战斗结束回调前复位 —— 这就是「**未作战时才可存档**」的落点；
- **手动保存每次都经过选档页**，因此既可写回当前档，也可写到其他档位；写入后所选档位成为
  当前档位（主菜单标题栏随之更新，之后的自动存档都记到它名下）。写回当前档是常规保存，
  不再弹覆盖确认；
- **读档入口有两处**：启动页「继续游戏」（无会话可释放）与主菜单「读取存档」
  （`showLoadSelection()`，先 `autoSave()` 把当前这局落盘到 `activeSlot`，再让玩家换档）；
  两处都复用 `loadFromSlot()`，因此提示文案与容错（空档 / 损坏 / 已结束）完全一致；
- `returnToStartScreen()` 是「离开这一局」的唯一出口（主菜单按钮 + 一轮结束）：
  `autoSave()` → `session / player / activeSlot` 置 `null` → `showStartScreen()`。
  它**不**调 `Platform.exit()`：进程退出仍只由 `bindStageEvents()` 的窗口关闭二次确认负责；
- 自动存档时机：`showMainMenu()`（回到主菜单）、`afterRogueStep()`（每通过一个路线节点后）、
  必然节点胜利后进入下一节点前、新游戏 / 新一轮建好会话后、`returnToStartScreen()`（离开这一局前）；
- 覆盖确认使用自定义按钮（「覆盖」/「取消」，默认取消），文案明确写出「旧进度与图鉴成长都会删除」；
  **只在覆盖「自己以外的已有档位」时询问**。

#### 5.1.1 「在同一档位开新一轮」的接线（v2.5）

`loadFromSlot()` 遇到已结束的一轮时，**不再**提示「本轮已结束，请返回」硬拒绝，而是：

```
loadFromSlot(slot)
  ├─ 空档 / 损坏 ──► 提示，留在选档页（原行为不变）
  └─ 载入成功且 session.isRogueRunFinished()
        ├─ 抛掉刚载入的死会话（结束的一轮没有可玩内容：advanceAfterNode 会一直返回 false）
        └─ offerNewRunInSlot(slot, cleared)
              ├─「开始新一轮」──► pendingNewRunSlot = slot
              │                   showStarterSelection(this::returnToStartScreen)
              │                     └─ 选完初始精灵 → chooseSlotForNewGame()
              │                          └─ pendingNewRunSlot != null
              │                               → 直接 confirmNewGame(该档位)（**不再选一次档位、不再问覆盖**）
              │                               → newRun + autoSave + 主菜单
              └─「取消」────────► 留在选档页
```

- `pendingNewRunSlot` 是「已经知道要写哪个档位、只等玩家选初始精灵」这一小段流程的状态；
  它在 `confirmNewGame` 里**用掉即清空**，在 `showStartScreen()` 里也**无条件清空** ——
  否则「取消过一次开新一轮」会让玩家下次点「开始游戏」莫名其妙跳过选档页；
- 新一轮**不需要覆盖确认**：玩家刚刚在弹窗里明确选了「开始新一轮」，再问一次是噪音。
  但选档页 `NEW_GAME` 意义上的「覆盖并开始」仍然会问（那条路径会清掉图鉴成长，性质不同）。

#### 5.1.2 「回退一步」（SL）的接线（v2.5）

`rollbackSlot(slot)`（`SaveSlotView` 的 `onRollback` 回调）**顺序是关键**：

```
rollbackSlot(slot)
  ├─ battleInProgress ──► 提示「请先结束当前战斗」，结束（绝不带战斗中途状态回退）
  ├─ confirmRollback(slot)（「回退到上一个存档点」/「取消」）
  ├─ session = saveManager.loadPrevious(slot)   ← ① 先确认备份能重建会话
  │     └─ 空（无备份 / 备份里没有可用精灵）──► 提示「没有可回退的存档点」
  ├─ saveManager.store().rollbackToPrevious(slot)  ← ② 再把备份落定成当前进度
  │     └─ SaveFormatException ──► 提示「上一个存档点已损坏」，**当前进度未受影响**
  ├─ activeSlot = slot; this.session = session; player = session.getPlayer()
  ├─ showMainMenu()（其中会 autoSave 一次）
  └─ 信息提示「已回退到上一个存档点」
```

顺序不能反：若先 `rollbackToPrevious` 落盘、再尝试 `loadPrevious`，则**备份损坏时后果不可恢复** ——
玩家既拿不到回退点，现在这份进度也已经被覆盖掉了。先读后写让失败路径只损失「回退能力」而不损失进度。

## 6. 版本兼容

| 场景 | 行为 |
| --- | --- |
| 存档缺少 `VERSION` 行 | 抛 `SaveFormatException`（这不是本作的存档，不猜着读） |
| `VERSION` 高于程序支持 | 抛 `SaveFormatException`，提示升级游戏 |
| 存档含程序不认识的键 | 跳过该行，其余照常解析 |
| **v1 旧档**（`RUN` 只有 3 个字段） | **可读取**：旧「点数」迁移为行动点，行动点上限补齐为同一值，`phase` 置空、金币记 0、`cleared` 记否；`OPTION`/`BOSS` 缺第 6 字段时按「未走过」处理 |
| v1 旧档的 `OPTION` 类型名已不存在（如 `ENEMY` / `RANDOM`） | 该节点被丢弃，其余照常读回 |
| 物种/技能/道具 id 已下架 | 该精灵 / 技能 / 道具被丢弃，其余照常读回 |
| 单个档位损坏 | 列表仍渲染 4 行，损坏档显示「存档已损坏或版本不受支持」且「继续游戏」不可选 |
| `phase` 字段无法识别 | 退化为 `RoutePhase.EXPLORING`（不因为一个枚举名拼错就整档报废） |
| **v2 文件缺少 `STORY` 行**（本改版之前的 v2 存档） | **可读取**：剧情线五个标记按「未开启」还原，本轮远征行为与旧版一致（不会凭空触发火箭队剧情线） |
| `STORY` 行字段不全 | 缺失字段按 `false` 处理（例如只写了 `STORY|1` 则仅「已开启剧情线」为真），不报错 |
| 手工删除 `save.prev.txt` | 一切照常，只是该档位失去「回退一步」（`canRollback()` 变假，按钮不显示） |
| `save.prev.txt` 内容损坏 | 档位列表与正常读档**不受影响**（`status()` / `read()` 只看 `save.txt`）；点「回退一步」时提示「上一个存档点已损坏」，**当前进度不被覆盖** |
| v2.4 及更早版本写出的档位目录（**没有 `save.prev.txt`**） | 直接可用：第一次进度变化时就开始产生备份，之后即可回退 |
| v2.4 及更早版本玩到「本轮已结束」的档位 | 摘要靠 `RUN` 行里的 `gameOver` / `cleared`（v2.0 起就有这两个字段）识别出来，卡片显示「开始新一轮」，可**在同一档位**开新一轮 |

`SaveData.FORMAT_VERSION` 当前为 **`2`**。任何**不向后兼容**的字段变化都必须提升它；
本次 1 → 2 虽然改了 `RUN` 行结构，但由于做了旧档迁移，**属向后兼容变更**；
`STORY` 是 v2 的**可选扩展键**，全 `false` 时不写出，因此**不构成格式版本变更**。

v2.5（上一个存档点 + 同档重开新一轮）**同样不动 `save.txt` 格式**：`save.prev.txt` 只是一份完整的旧
`save.txt`（同格式、同解析器，因此无需迁移）；「开始新一轮」只删进度文件、不碰成长文件。
因此 v2.5 之后的任何改动只要能读 v2.4 的档，就能读 v2.5 之前的档，反之亦然。

## 7. 已知限制

- 存档**不含战斗中途状态**：战斗场景由引擎持有现场，因此设计中即要求「未作战时」存档；
  玩家在战斗中无法保存，战斗结果落定后由 `afterRogueStep()` 自动落盘。
- **存档不含商店库存与战斗随机种子**：读档后商店商品会重新抽取，不影响进度正确性。
- **必然节点的「已重试一次」用 `retryUsed` 记录**，未区分是道馆还是四天王 —— 因为二者都只允许
  失败一次且不会在同一段内连续出现（道馆失败会重开本段，四天王在末段道馆之后）。
- 图鉴成长以 `GrowthProgress` 为单位存储在**档位目录内**，更换档位即换一份成长记录；
  `GrowthProgress.instance()` 的全局文件**不再**被新档位使用。
- **已结束的一轮（通关 / 战败）仍会随 `autoSave` 落盘**（否则最终队伍状态与图鉴成长会丢），
  因此档位文件里可能留着「本轮已结束」的快照；`SaveSummary#finished()` 把它**显示**出来
  （角标「本轮已通关 / 本轮已战败」+ 按钮改「开始新一轮」），玩家选定后可在**同一档位**开新一轮，
  而不是被迫另找空档位。续玩这个档位本身（`load`）只会得到一个没有可玩内容的死会话，
  因此控制器改为引导开新一轮（见 §5.1.1）。
- **「回退一步」只保留一个存档点**：`save.prev.txt` 只留最近一份，因此是「退一步」而不是
  「存档树 / 无限回溯」。想要多步回退只能在关键节点前**另存到别的档位**（4 个档位即 4 条时间线）。
- **回退只回退进度快照，不还原图鉴成长**：成长是局外累积数据（个体值加成），回退它等于惩罚玩家
  之前几轮的努力，且会让「同一档位反复游玩」的收益归零。
- **回退是按档位手动触发的，不是自动的**：程序不会替玩家判断「刚才那个节点该不该重来」。
- 未实现存档位重命名 / 复制 / 导出。
